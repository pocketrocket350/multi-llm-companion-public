# 長期記憶

会話から今後も役立つ情報を保存し、関係する次回以降の会話に使います。既定では候補を自動承認します。確認してから使いたい場合は、設定で確認待ち方式に切り替えられます。お知らせは会話本文や音声読み上げには含まれません。

## 使い方

1. 右上の「設定」→「会話・音声」→「記憶を管理」を押します。
2. 一覧から内容を選び、状態・作成日時・根拠の会話を確認します。
3. 内容と分類を確認し、必要なら直します。
4. 確認待ち方式の場合は、使ってよい内容なら「承認して保存」を押します。承認済みの内容を直したときは「修正を保存」を押します。
5. 使わない候補は「保存しない」、不要になった内容は「選んだ記憶を削除」を押します。

「すべての記憶を削除」は元に戻せません。会話で「覚えないで」「記憶しないで」と書いた発言は保存しません。「忘れて」と書いた場合は対象を一意に特定できるときだけ削除します。対象を特定できない場合は削除せず、記憶の管理から選べるように案内します。

## 停止する方法

「今後の会話で保存した記憶を使う」は、保存済みの記憶を会話へ渡す状態です。「記憶を管理」を開き、先頭のチェックを外すと停止します。停止しても保存済みの記憶は消えません。再び使うにはチェックを入れます。

## 保存と安全性

記憶は会話履歴と同じSQLiteデータベースへ保存されますが、会話履歴を削除しても保存済みの記憶は消えません。必要なら記憶の管理から別に削除してください。

呼び名、使用言語、明示した境界、継続的な好み・習慣・重要な事実を保存対象にします。APIキー、パスワード、認証情報、一時的な感情・体調、AIが推測した恋愛・依存・親密さ、一回限りの雑談は保存対象から外します。ただし完全な自動判定はできません。個人情報、会社や学校の秘密、公開したくない内容は入力しないでください。

外部LLMを使う場合、承認済みで今回の話題に関係する記憶だけが、回答作成の参考情報として選択中のAPIサービスへ送られます。会話画面の「使用した記憶」は、その応答で参照した記憶を必要なときだけ確認するための表示です。

## 関連する設定

`local/memory.yaml` では、通常は変更不要ですが、次の値を調整できます。

```yaml
auto_approve_candidates: true
min_relevance_score: 2
duplicate_similarity_threshold: 0.75
max_memory_age_days: 365
max_recent_messages: 12
summary_max_characters: 900
```

`auto_approve_candidates` は既定で `true` です。通常は「設定」→「会話・音声」→「記憶を管理」を開き、「候補を自動承認する」のチェックで切り替えます。`false` にすると、候補は確認待ちで保存され、承認するまで会話の参考には使いません。`min_relevance_score` を大きくすると、より強く関係する記憶だけが使われます。`duplicate_similarity_threshold` を小さくすると、似た記憶をより積極的に1件へまとめます。保存後の修正・削除は、記憶の管理からいつでも行えます。

`max_memory_age_days` は保存済み記憶を会話の参考として使う期間です。期限を過ぎても記憶を削除しません。`0` にすると期限なしです。`max_recent_messages` より古い会話は、その場で短い要点へ整理して外部LLMへ送信範囲を抑えます。履歴を削除したり、要点を別の記憶として保存したりはしません。
