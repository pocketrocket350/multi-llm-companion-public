# 設定・履歴・記憶のバックアップと復旧

この手順はWindows 11のソース版向けです。専用インストーラーやバックアップボタンはありません。既存のファイルコピーとWindowsの設定保存を使います。バックアップは個人用で、配布候補や公開リポジトリへ入れないでください。

## 保存される場所

| 内容 | 既定の保存先 | 注意 |
| --- | --- | --- |
| 会話・画像の履歴、記憶、感情 | `data/conversations.db` | 記憶も同じDBにある。履歴だけの削除では記憶は消えない |
| 接続先・人格・音声・記憶・表示・VMD登録 | `local`内のYAML | 素材の絶対パスがあれば別PCで修正する |
| PMX・VMD・テクスチャ・認識モデル等 | `local`内の各フォルダー | 利用条件を守った個人用コピーに限る |
| 画面サイズ、音声操作、検索・画像の許可等 | WindowsのQSettings | `local`には保存されない |
| 環境変数と`.env` | Windows側とアプリ直下 | 秘密を含み得る。公開・画面共有しない |

`local/app.yaml`の`database_path`を変更している場合は、その実際のDBと隣の`-wal`・`-shm`ファイルの保存先も対象です。素材が`local`外にある場合、その素材はこのフォルダーのコピーに入りません。外部サービスの契約、ボイスライブラリ、環境変数はフォルダーコピーだけでは復元できません。

既存の環境変数 `MULTI_LLM_COMPANION_HOME` を設定している場合、アプリはその保存先を優先します。復元先のフォルダーを必ず使うには、そのフォルダーでアドレス欄に`cmd`と入力して開き、`set "MULTI_LLM_COMPANION_HOME="`、続けて`run.bat`を実行してください。このコマンド画面の中だけで指定を外し、通常のWindows設定は変更しません。

## 1. 終了してからバックアップする

目的は、設定とDBを同じ時点の内容で保存することです。初回は変更前に一つ作ります。

1. 会話の生成・録音が終わるまで待ちます。検索中なら「検索・返答を取消」、読み上げ中なら「音声・動作を停止」を押します。ボタンは処理中だけ表示されます。
2. ウィンドウ右上の「×」を押します。「処理中です」などが出たら終了を待ち、もう一度閉じます。アプリ画面が消え、起動元のコマンド画面が終了したことを確認します。終了できない状態のDBを普通のファイルコピーで保存しないでください。
3. エクスプローラーで、アプリの外に新しい個人用フォルダーを作ります。例は「ドキュメント」の`companion-backup-20261010`です。既存バックアップを上書きしません。
4. アプリの`local`と`data`フォルダーを、この新しいフォルダーへ**コピー**します。移動しません。DBに`-wal`・`-shm`が残っている場合も、同じ時点の関連ファイルを一緒にコピーします。別の`database_path`なら、そのDB一式もコピーします。
5. `.env`を使っている場合は、エクスプローラーの「表示」→「表示」→「隠しファイル」と「ファイル名拡張子」を有効にして、個人用バックアップへコピーします。APIキーは通常Windows環境変数から渡します。キーの値をメモや報告へ転記しません。別PCでは安全な管理先から再設定します。
6. 画面の好みも保存するなら、アプリが終了したまま、バックアップフォルダーのアドレス欄へ`cmd`と入力してEnterを押します。開いたコマンド画面で次を実行します。

```bat
reg export "HKCU\Software\multi-llm-companion\desktop-companion" "window-settings.reg"
```

7. 「この操作を正しく終了しました」と表示され、バックアップ内に`window-settings.reg`があることを確認します。キーが存在しない場合は、画面設定のバックアップなしとして記録し、DBとYAMLのバックアップは保持します。既存ファイルへの上書き確認が出たら中止し、別の新しいフォルダーを使います。

バックアップを開いて、YAMLとDBのファイルが存在することを確認します。個人用バックアップは秘密や会話を含み得るので、公開ストレージへ共有しません。`.venv`はバックアップから移植せず、新しい場所でセットアップします。

## 2. 空の復元先で確認する

目的は、元のデータを失わずに復元の成否を確かめることです。別の空のアプリフォルダーを用意し、元の環境へいきなり上書きしません。

1. v1.0候補を別フォルダーへ展開し、`setup_windows.bat`を実行します。「セットアップが正常に終わりました」を確認します。先に元のアプリは終了します。
2. 復元先にできた`local`と`data`を、それぞれ`local-before-restore`、`data-before-restore`へ名前変更します。削除しません。
3. バックアップの`local`と`data`を復元先へコピーします。独自の`database_path`は元の環境を指したままにせず、復元先にコピーしたDBへのパスへ変更します。絶対パスのPMX/VMD・認識モデル・背景も復元先に合わせます。
4. `.env`が必要なら、復元先の見本`.env`を`.env-before-restore`へ名前変更してから、個人用バックアップをコピーします。外部LLMを呼ばずに確認する場合は、**復元先だけ**の`local/app.yaml`で`active_provider: mock`にします。
5. 表示・操作の好みも戻す場合だけ、元のアプリを終了したまま、バックアップフォルダーで開いたコマンド画面から次を実行します。これはWindows利用者のアプリ共通設定へ反映されます。別フォルダーごとに独立した画面設定にはなりません。

```bat
reg import "window-settings.reg"
```

6. 復元先の`run.bat`を開きます。左上の時計アイコン「履歴」を押し、保存した会話を選びます。本文が戻り、新しい会話ができることを確認します。

`reg import`は同じキーの保存値を戻します。バックアップにない、後から追加した設定を自動的に消す操作ではありません。通常のレジストリを一括削除して合わせないでください。
7. 右上の歯車「設定」→「会話・音声」→「記憶を管理」を開き、保存した記憶の本文・有効状態が戻ることを確認します。画面の好みを戻した場合は、画面サイズやチェック状態も確認します。
8. もう一度アプリを終了し、復元先の`run.bat`で再開して、追加した会話も履歴に残ることを確認します。これが復元成功の条件です。破損エラー、履歴欠落、別のDBへ保存される場合は失敗です。

失敗したら復元先のアプリを終了し、そこでの利用を止めます。バックアップと元の環境は保存したまま、元フォルダーの`run.bat`から再開できます。復元先の退避設定を戻すときも、現状を別名で退避してから戻します。元のDBを削除して作り直したり、古いバックアップで新しい会話を上書きしたりしません。報告には操作番号・秘密を隠したエラー文・使ったバックアップの日付だけを添え、会話全文やキーは送りません。

## 3. 起動できない・機能が動かないとき

| 表示・症状 | 次の操作 | 再開の条件 |
| --- | --- | --- |
| Pythonが見つからない | Python 3.12を導入し、フォルダーを開き直す | セットアップがPython 3.12を検出する |
| 仮想環境作成・pipが失敗 | エラーを確認。フォルダーの書込み権限、TEMP/TMPの書込み先、ネット接続を確認 | 原因を直した後のセットアップが成功する |
| 既存`.venv`のPython版が違う | アプリ終了後に`.venv`を`.venv-before-recovery`へ名前変更し、セットアップを実行 | 新環境で起動する。設定・DBは触らない |
| 設定ファイルが見つからない | `setup_windows.bat`を実行して不足した見本を作る | 既存設定は上書きされない |
| YAMLの書式・設定内容が不正 | エラーに出たファイルを退避し、直前の編集を戻す | 起動する。セットアップだけでは既存の誤設定は直らない |
| APIの設定不足・認証エラー | 「設定」→「会話・音声」→「LLM接続・マイクの設定」で接続設定を確認。キーはWindows環境変数に設定 | Mockで独立した文字会話を使える。実接続は正しい資格情報が必要 |
| VoiSona・マイク・PMXが使えない | [音声](audio_ja.md)・[アバター](avatar_ja.md)の設定と利用者所有素材のパスを確認 | 接続先・素材が利用可能。問題が続くなら音声・3Dを無効にした文字会話で復旧 |
| 履歴の破損・保存失敗 | 上記の空の復元先でバックアップを検証 | 元DBを保持し、復元先で履歴と新規保存に成功する |

同じ失敗を繰り返さず、解決しない場合は停止し、操作番号とエラーを控えます。権限の一括変更、DBの直接編集、素材削除で回避しません。

Codexは人工DB・隔離INIの復元に加え、通常アプリとは別の人工Windowsレジストリキーで `reg export` / `reg import` とQSettings値の一致を確認しました。試験キーは回収し、通常のレジストリは上書きしていません。別PCへの環境変数・ボイスライブラリ移行とクリーンWindowsの受入は別に残ります。
