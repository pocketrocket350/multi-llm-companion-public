# アバター表示とMMD設定

アプリは2Dの確認用アバターと、利用者が用意したPMXを描画するMMD表示に対応します。MMD表示では、音声に同期する口形、表情、視線、会話動作、VMD、IK、物理を一つの姿勢へ合成します。

## 画面の見方

画面は左にアバター、右に会話です。配布版の初期値は汎用2Dアバター「紬」で、雨衣のPMXは同梱しません。雨衣MMDは利用者が正規に取得してローカルへ導入した場合の基準構成です。PMX表示中はモデル右上の人物アイコンで全身／バストアップを切り替え、表示領域の境界をドラッグして幅を調整します。技術的な状態は「設定」→「診断情報」で確認します。[最新の操作手順](development/phase11-user-check_ja.md)を参照してください。以下には描画方式別・過去段階の説明も含みます。

- 表情: 会話ごとに保存された感情と強さを表示します。
- 動作: LLMが `gesture` を返した場合に表示します。`wave` は手を上げる簡単な表示になります。
- 視線: LLMが `gaze` を返した場合に表示します。`left`、`right`、`up`、`down` は目線の向きへ反映されます。
- 動き: 音声依頼後は「音声開始待ち」、推定口形が始まると「音声再生中」と表示します。`wave` は手を振り、`nod` はうなずきます。
- 口形: `推定 あ` のように、文章から推定した母音を表示します。音声を直接解析した結果ではありません。
- 口形モニター: PMXメッシュプレビューでも、現在の推定口形を大きな楕円と「あ・い・う・え・お」の選択表示で確認できます。これは確認用の図形です。
- 顔モーフ拡大ビュー: PMXの口・表情モーフが設定されている場合は、それらに関係する三角形面を大きく表示します。全身表示では見えにくい「あ・い・う・え・お」、目、眉、口角などの変形を確認するための簡易表示です。
- PMX表情モーフ: `適用中 笑顔（60%）` のように、実際にメッシュへ適用できる表情名と強さを表示します。設定名がPMX内にない場合も日本語で表示します。
- PMXボーン: `適用中（視線 両目 / 姿勢 頭）` のように、実際に変形へ使う目・頭・上半身ボーンを表示します。設定名がPMX内にない場合は変形せず、日本語で案内します。
- 常時動作: 待機、短い瞬き、自然な揺れを表示します。通常設定の「動きを表示」チェックは撤去し、採用済みの動作を常に有効にしています。会話中の割り込みは実行中の「音声・動作を停止」を使います。
- 動作ミキサー: 手振り、視線、表情、VMD、物理が重なった場合の優先順位を管理します。新しい発言では古い会話動作を中断し、計算途中の古い姿勢を表示しません。
- 「音声を停止」: VoiSona Talkへ送った直近の音声リクエストを停止します。
- 「3D連携」: Mockの接続状態、またはPMXメッシュプレビューの読込状態を表示します。PMXを読み込むと2Dアバターの代わりに三角形面の形状プレビューを表示します。

## 表示名と色の変更

初回セットアップ後、`local/avatar.yaml` をメモ帳で開くと、表示名、髪色、服色、リボン色を変更できます。色は `#684765` のような6桁の16進数で指定します。設定ファイルにAPIキーは書きません。

この設定はオリジナルアバターの見た目だけを変えます。VoiSona Talkのボイスライブラリや、既存キャラクターの名前・デザインを設定しないでください。

## 3D連携Mockの確認

`local/avatar.yaml` に次の設定を追加してアプリを再起動すると、画面に「3D連携: 3D連携Mock（接続済み）」と表示されます。

```yaml
three_d:
  enabled: true
  provider: mock
```

Mockは外部通信も3Dモデル読込もせず、会話の `emotion`、`gesture`、`gaze` を将来の3D表示と同じ入口へ渡します。安全に接続構造だけを確認するためのものです。MMDモデル、テクスチャ、モーションは設定・リポジトリへ追加しません。

## PMXモデルのメッシュプレビュー

1. 利用規約と再配布条件を確認済みのPMXモデル一式を、`local/models/mmd/モデル名/` のようなフォルダへ置きます。
2. PMX本体のパスを、`local/avatar.yaml` へ記載します。
3. アプリを再起動します。

```yaml
three_d:
  enabled: true
  provider: pmx_preview
  model_path: local/models/mmd/モデル名/model.pmx
```

画面にはPMXの三角形面を描いたメッシュプレビューが表示され、ドラッグで向きを変えられます。設定済みの口・表情モーフと、目・頭・上半身のボーン姿勢を反映します。第39段階では、親子関係に加えて付与変形、固定軸・ローカル軸、変形階層、IKリンクごとの角度制限を読み取り、密なGPU表示と予備表示で同じ姿勢計算を使います。非常に大きなモデルでは、安全のため点群表示へ自動的に切り替わります。

PMXモデルは `local/models/mmd` の外からは読み込みません。モデル本体やテクスチャをGitへ追加しないでください。

## 表情プリセットとPMXモーフの対応付け（第36段階）

PMXモデルでは、笑顔や眉のモーフ名がモデルごとに異なります。第36段階では、キャラクター共通の表情とPMX固有名を分けます。

- `expression_presets`: 「やさしい笑顔」などの表情と、意味上の役割・基準強度
- `emotion_presets`: happyなどの感情から、使う表情プリセットを選ぶ対応表
- `mmd_mapping.expression_morphs`: smileなどの役割から、そのPMX内の実名へ変換する対応表

この分け方により、別のPMXへ変更しても、表情の意味や強さは残したまま、最後のPMX名だけを書き換えられます。

```yaml
three_d:
  enabled: true
  provider: pmx_preview
  model_path: local/models/mmd/モデル名/model.pmx
  expression_presets:
    neutral_soft:
      morphs:
        soft_smile: 0.06
    gentle_smile:
      morphs:
        smile: 0.35
        eye_smile: 0.18
        blush: 0.04
  emotion_presets:
    neutral: neutral_soft
    happy: gentle_smile
  mmd_mapping:
    expression_morphs:
      soft_smile: "微笑み"
      smile: "笑顔"
      eye_smile: "にこり"
      blush: "頬染め"
    # 旧方式も引き続き読み込めます。新規設定ではexpression_morphsを使います。
    emotion_morphs:
      sad: "悲しい"
    mouth_morphs:
      a: "あ"
      i: "い"
      u: "う"
      e: "え"
      o: "お"
    gaze_bones:
      user: "両目"
      forward: "両目"
      left: "両目"
      right: "両目"
    gesture_targets:
      wave: "右腕"
      nod: "頭"
```

回答後、状態欄には表情プリセット名と、実際に適用するPMXモーフ名・強さが表示されます。PMXに存在しない設定名は「未検出」と表示されます。口パクは別の高速経路、まばたきは自然動作の経路を使うため、表情プリセットを切り替えても互いを解除しません。

## PMX口モーフの設定（第16段階）

口モーフとは、口の周辺の頂点を動かして「あ・い・う・え・お」の形を作るPMX内のデータです。第16段階では、`mouth_morphs` に設定した頂点モーフを、VoiSonaに合わせた推定口形としてメッシュへ反映します。

アプリ起動時、アバター欄に `PMX口モーフ候補:` と表示される場合は、その候補名を確認して `local/avatar.yaml` の右側へ記入してください。候補が `あ、い、う、え、お` と表示されるモデルでは、上の設定例をそのまま使えます。

候補が表示されない、または候補が頂点モーフではない場合は、メッシュ本体を変形できません。その場合でも、口形モニターは引き続き表示されます。モーフ名を推測して設定しないでください。

第16段階では頂点口モーフまでを反映し、第17段階で頂点表情モーフ、第18段階で目・頭・上半身ボーンを追加しました。VMDモーション再生はまだ実行しません。

## PMXボーンの設定（第18段階）

`gaze_bones` には、利用者を見るときと左右・上下の視線に使う目ボーン名を書きます。`pose_bones` には、うなずきに使う頭と上半身のボーン名を書きます。`gesture_targets`には説明文ではなく、PMX内に実在する`右腕`などのボーン名を書きます。

```yaml
mmd_mapping:
  gaze_bones:
    user: "両目"
    forward: "両目"
    left: "両目"
    right: "両目"
    up: "両目"
    down: "両目"
  pose_bones:
    head: "頭"
    upper_body: "上半身"
```

第26段階ではBDEF1、BDEF2、BDEF4、QDEF、SDEFの基本ウェイトと、親子ボーン変形を使います。設定した視線・うなずきは密なGPU表示にも反映されます。PMXが持つIKボーンの目標・関節列・反復回数も読み取り、対応付けたIKボーンを小さく動かす場合に限り、簡易的なIK計算を行います。関節ごとの細かな角度制限、付与親、VMDは未対応です。

## PMX物理演算

PMXの剛体とジョイントを読み取ります。剛体は髪やスカートの一部などに重さを与える部品、ジョイントはそれらをばねのようにつなぐ部品です。

既定物理はBullet 2.75の6自由度ばね制約を使うネイティブバックエンドです。MMD座標からネイティブ空間への長さ倍率`0.08`、120Hz固定刻み、4回のソルバー反復、PMX保存値どおりの衝突グループ・マスクを使用します。現在のVMD・会話姿勢から運動学的剛体を作り、物理結果をボーン差分としてMotion Mixerの最下位層へ戻します。「動きを表示」をオフにすると、VMDや自然動作と一緒に物理も停止します。

公式PMX、剛体、ジョイント、設定済みVMDは変更しません。独自の薄布メッシュ補正、補助手のひらによる押し出し、独自衝突方式も使用しません。ネイティブ物理を利用できない場合に備え、安全なPanda3D Bulletへの復帰経路を維持します。

## VMDモーション再生（第28段階）

VMDは、MMDで使うモーションファイルです。利用条件を確認済みのVMDは `local/motions/`、権利確認記録は `local/licenses/` へ置いてください。PMXとVMDはリポジトリへ追加してはいけません。

外部VMDはファイルパスを直接書かず、権利記録とモデル適合条件を持つローカルVMDカタログから識別名で選びます。`vmd_path`の直接指定は現在の設定検証でエラーになります。

```yaml
three_d:
  enabled: true
  provider: pmx_preview
  model_path: local/models/mmd/モデル名/model.pmx
  vmd_catalog_path: local/vmd_catalog.yaml
  vmd_motion_id: idle_motion
  motion_library_enabled: true
```

第38段階以降は、VMDのボーン位置・回転を30fps基準で再生し、X・Y・Z移動と回転に保存された個別のベジェ補間曲線を使います。回転はクォータニオンの球面補間で、同じ姿勢へ遠回りしないようにします。右側の状態に `VMD再生: ファイル名` と出れば読み込み済みです。

口形と表情の状態は、3Dモデルの顔へ重ねず、3D欄の上にある `アバター: ...｜口形: ...｜表情: ...` へ表示します。口パクや眉を確認するときに、この文字が顔を隠すことはありません。

## 表情・視線・口パクのMMD統合（第29段階）

第29段階ではVMDの表情モーフも読み、同名のPMXモーフへ合成します。会話の感情モーフ、視線ボーン、VoiSonaの音素時刻（取得できない場合は文章推定）による「あ・い・う・え・お」の口モーフも同時に反映します。音声停止時には口を閉じます。`まばたき` または `瞬き` というPMXモーフがあるモデルでは、短い自動まばたきも重ねます。

口形が動くには、`local/avatar.yaml` の `mouth_morphs` に、そのPMX内の実在するモーフ名を設定します。画面の「口形: 音声同期 あ」などの表示だけではモーフ反映の確認になりません。口が見えるよう、バストアップ表示では顔の高さを中心にします。自然待機VMDは表情・まばたき・口形を含めず、既存の常時動作とリップシンクへ任せます。

自然待機VMDを生成する開発用ボタンは2026-09-22の設定整理で通常UIから撤去しました。既存の生成器は互換・内部検査用に残しています。日常利用では採用済みの待機動作を使います。

内部生成器を利用する開発作業では、原本とカタログを保護し、利用条件・対象ボーンを確認してから別途登録します。通常利用者へ生成操作は案内しません。

## VMD互換機能（第42段階）

第42段階では、VMDの対象モデル名、カメラ、照明、セルフ影、モデル表示・IK切替も読み取ります。IK名がPMXのIKコントローラー名と一致すると、該当フレームの有効・無効を足・つま先などのIK計算へ反映します。見つからないボーン、モーフ、IKは状態欄の`VMD互換`へ表示します。最大ボーン移動量/PMX身長も体格差の診断値として表示しますが、自動補正や特定VMD向けの名前置換は行いません。

カメラ・照明のキーがあるだけでは通常会話の表示を変更しません。VMDカメラ・照明は内部互換処理に残しますが、通常設定の選択肢は全身／バストアップだけです。

セルフ影、モデル表示切替、平行投影カメラはデータを読み取り、状態欄へ`未対応`と表示しますが、描画へは適用しません。影フレームが存在しても標準描画品質を下げず、対応済みとも表示しません。

ループ終端と先頭の姿勢が異なるVMDは、境界を最大0.25秒で補間します。会話VMDの切替、音声終了、利用者割り込みもMotion Mixerが現在姿勢から待機姿勢へ段階的に戻します。外部VMDより会話ジェスチャー、視線、会話表情を優先し、音声同期の口形と自動まばたきはVMDから保護します。

第42段階は、実PMX/VMDのカメラ、照明、IK、ループと、hck_cameraのカメラ専用VMDを利用者が確認し、受け入れ済みです。読み取りのみのセルフ影、モデル表示切替、平行投影カメラは引き続き未対応です。

## 音声・感情・動作表現の統合（第43段階）

第43段階では、会話ごとの平滑化済み感情を一つの`ExpressionPlan`へ変換し、PMX表情、視線、ジェスチャー/VMD、自然動作へ別々の強度を渡します。最大値は表情0.82、ジェスチャー/VMD 0.68、視線0.50、自然動作0.32です。入力の`emotion_intensity`を全経路へ直接掛けません。LLMが明示した動作は、感情がneutralまたは強度0でも動作上限を使い、選択済み動作だけが無音化される状態を避けます。

画面の`表現統合`には、音声、表情、動作、視線、自然動作の適用値と、無効、安全補正、ボイス固有スタイル未対応が表示されます。PMXの表情プリセット基準値とVMDカタログの`intensity_scale`は、出力別強度へ最後に掛けるモデル・素材固有の係数として維持します。VMDのボーン姿勢は絶対角度を0へ縮小せず、待機VMDの姿勢と会話VMDの姿勢をこの係数で補間します。

利用者が音声停止、次の送信、マイク入力を行うと、同じ親発話世代から音声、口形、表情、視線、ジェスチャー/VMDを解除します。Dense側もMotion Mixerのrevisionを進めるため、停止前に始まった非同期姿勢計算はGPUへ反映されません。新しい回答は新しい世代だけを使います。

既存の`physics → VMD → idle → gesture → gaze → expression`優先度は変更していません。口パクと自動まばたきも従来の保護経路を使います。割り込み後は古い会話表現を再開しませんが、次の会話または待機状態の自然動作は新しい状態として続きます。

利用者は、音声表現を無効にした従来動作と、有効時の実VoiSona・実PMX画面を確認し、第43段階を受け入れ済みです。

## PMX表情モーフの設定（第17段階）

`emotion_morphs` には、感情名とPMX内のモーフ名の組み合わせを書きます。たとえば `happy: "笑顔"` は、LLMの感情が喜びになったときに、PMX内の「笑顔」というモーフを使う設定です。頂点モーフと、頂点モーフをまとめたグループモーフに対応します。

これは第36段階以前の互換方式です。既存の`local/avatar.yaml`は変更しなくても動きます。新しく設定する場合は、上の`expression_presets`、`emotion_presets`、`mmd_mapping.expression_morphs`を使ってください。両方に同じ感情がある場合は、新しいプリセット方式を優先します。

第43段階では、表情の変形量に`emotion_intensity`を直接使わず、表情専用の曲線と上限で作った強度を使います。その値へ表情プリセットの基準強度を掛けます。口と表情が同じ頂点へ作用する場合は両方を元の頂点へ加算するため、笑顔の途中でも口パクが失われません。表情を切り替えるときは、短い時間をかけて強さを移動します。

雨衣PMXの`照れ`、`涙`、`汗`、`ムカッ`、`青ざめ`、`ハイライト拡大`、特殊な瞳などは、顔形状を少しずつ変えるモーフではなく、隠れた表示物を所定位置へ移すモーフです。実描画で中間値では見えないことを確認したため、組合せで1.0にした場合は、会話の表情強度が0より大きければ1.0のまま適用します。0.2など1.0未満を明示した場合は、従来どおり表情強度を掛けます。通常の目、眉、口、顔全体のモーフも従来どおり連続的に強さが変わります。

画面に `PMX表情モーフ: 設定名「笑顔」が見つかりません` と表示された場合は、`local/avatar.yaml` の名前とPMX内のモーフ名が完全に一致していません。PMXに実在する候補名を確認して設定してください。第41段階では頂点、UV、追加UV、材質モーフと、それらへ展開できるグループモーフを描画へ適用します。ボーンモーフは対象外です。

アバターは会話を送信したあとに更新されます。同じ会話を開き直すと、保存済みの最後の表情・動作・視線を表示します。第29段階ではVoiSona Talkが生成した一時WAVをWindows側で再生し、その実時間へ口形予定を合わせます。APIが音素ごとの開始・終了時刻を返す場合はその時刻を使い、画面に `口形: 音声同期` と表示します。時刻がない場合は日本語文章から母音を推定し、`口形: 推定` と表示します。LLMがJSON形式の共通回答を返さなかった場合も、speech本文があれば口形を推定します。

## LLMへ依頼する値

アプリはLLMへ、次の値を依頼します。

- `gesture`: `none`、`wave`、`nod`
- `gaze`: `user`、`forward`、`left`、`right`、`up`、`down`

対応外の文字が返っても、画面には短い状態名として表示します。会話そのものは失われません。

## 3DアバターとMMD

3D表示は、PMXのボーン、IK、BDEF・SDEF、頂点・材質・UVモーフ、Toon、スフィア、透明材質、輪郭、VMD、ネイティブBullet物理を一つのMMDランタイムとして処理します。通常表示では利用者カメラと固定照明を維持し、VMDの透視カメラ・照明は明示選択時だけ使います。セルフ影、モデル表示切替、平行投影カメラは、基準体験に必要かを最終品質フェーズで判断します。

会話側は`emotion`、`emotion_intensity`、`gesture`、`gaze`という抽象値を渡し、モデル固有のモーフ、ボーン、VMDへの対応はアバター層で解決します。MMDモデル、モーション、テクスチャ、音声の利用規約は素材ごとに確認し、公開できない素材は`local`配下だけで使用します。
