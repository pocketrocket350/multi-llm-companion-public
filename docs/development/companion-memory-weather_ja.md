# 自動記憶と天気の会話の修正（2026-09-25）

## 変更と原因

検索・画像を含む会話では、外部情報から利用者の記憶を作らないため、モデルの記憶候補を除外していた。その後の通常会話で「私はモトジムカーナが大好きです。モトジムカーナって知っていますか？」と話しても、ローカルの補完が呼び名・予定しか扱わず、本人の好みも保存されなかった。

この保護を残し、本人が入力先頭で「私は○○が好き／大好き／苦手」と明言した文をローカルで候補にする。後続の質問は保存しない。自動承認がオンなら承認済み、オフなら確認待ち。記憶を無効にした場合、保存拒否・否定・仮定・引用・秘密情報の場合は自動保存しない。既存の重複判定・訂正・忘却の経路を使う。一人称の訂正も保存した「ユーザーは」と対応させ、候補出力がなくても旧値を置き換える。過去の通常会話を一括再解析したり、通常DBに今回の試験文を追記したりしない。

入力途中に現れていた検索の説明と天気の地域専用欄は撤去した。地域なしの「今日の天気」は普通に会話として送信され、地域を普段の口調で一つ尋ねるよう会話生成へ伝える。その直後の「東京都千代田区だよ」「東京です」などの地域回答から検索へ進む。検索へ渡すのは地域・対象時期から作る短い検索文と現在日時で、前の会話本文・保存記憶は渡さない。地域を含めて質問した場合はそのまま検索する。別話題、新しい会話、能動発話の介在、検索無効化、中断の境界を守る。

検索許可の切替と送信範囲の説明は設定、出典は返答のそば、処理表示と取消は実行中だけに配置する。位置情報は取得しない。依存関係・公開API・設定形式・DBスキーマ・保存形式の変更なし。

## 確認の区別

- 実装済み：上記の保存漏れと会話操作の修正。
- 自動テスト：実行結果は下の検査記録に追記する。正常経路だけでなく、外部情報の誤保存・検索の取消・無効化・遅着結果を含む。
- Codex環境の統合確認：空のDB・隔離設定・QSettingsと実PMXのウィンドウで、ニュースのモック検索後の好み保存、記憶一覧、地域の聞き返し、地域回答→出典付きの返答、普通の会話への復帰を確認。`local/diagnostics/companion-memory-weather-20260925/isolated-a31c0150/result.json`、`memory.png`、`turn-2.png`。LLM・検索はモックであり、返答例を実LLMの成功と数えない。
- 未実行：今回の追加の有料実API評価、実音声の再評価。先の承認枠は使用済み。人格を使う実LLMの聞き返しの自然さは利用者の会話での受入待ち。
- 制約：これは一般的な日本語の事実を完全に理解する記憶抽出器ではない。推測を避けた明確な本人の好みを補完する。地域回答も明記された行政区名・都道府県名を扱い、「うち」「いつものところ」から場所を推測しない。

## 普段の操作と受入条件

1. アプリを閉じ、いつもの `run.bat` から再起動する。検索と記憶の設定をオンにして使っていた場合は、その設定をそのまま使う。
2. 普段の会話の中で「私はモトジムカーナが大好きです。モトジムカーナって知っていますか？」と送れる。今後のために同じ話を一度伝えることで保存される。設定の「記憶を管理」には好みだけが1件表示され、後半の質問は記憶されない。
3. 天気を知りたい時は通常の入力欄で「今日の天気」と送る。地域が未指定なら雨衣から地域を尋ねる返答が来る。「東京都千代田区だよ」と答えると検索し、予報と出典が返答の近くに出る。最初から「今日の東京都千代田区の天気を教えて」と送ってもよい。専用の地域フォーム・確認ダイアログは出ない。
4. 話題を変えたい時は普通に別の話を送る。検索中に止めたい場合は「検索・返答を取消」、読み上げを止める場合は「音声・動作を停止」。停止後に古い返答を再開せず、通常会話へ戻れることが成功条件。
5. 記憶が増えない、同じ内容が増え続ける、専用欄が再び出る、地域を答えても検索しない場合は、その入力と画面の表示が不具合の手掛かりになる。自動テストや隔離検査を利用者が繰り返す必要はない。
