# 設定の見切れ・プレビュー・外部機能設定の修正

**現行仕様（2026-09-28確認）**：Web検索・画像送信の許可は初回オンで、変更した値は再起動後も保持する。[設定保持の後続修正](settings-persistence_ja.md)を参照。以下の「起動中だけ」は当時の履歴。全身／バストアップはモデル右上の人物アイコン、幅変更は境界ドラッグを使う。[現行の操作案内](phase11-user-check_ja.md)。

作業開始2026-09-22、更新2026-09-23。利用者の追加指摘に対する範囲・判定条件。

- LLM接続・マイク設定は小さい画面と150％倍率でも右端が切れず、全入力欄へ到達できる。
- モーションの選択時に全身表示で一度だけ再生する。再生停止で通常待機へ戻り、管理画面終了で元の表示範囲へ戻る。通常のVMD・カタログ・速度は変更しない。
- モーション・表情の水色の描画異常を実PMXで再現し、原因を特定して修正する。元の素材・表情設定は変更しない。
- 会話に使用しない、または利用不可の項目は薄い文字と状態名で区別する。再有効化や編集のための選択は残す。
- 利用者の最新指示によりWeb検索・画像送信の許可は標準オンへ変更する。設定画面に移し、オフ操作と遅着結果破棄を維持する。検索の詳説切替は撤去し、必要なら会話文で詳しい説明を頼める。
- 許可だけで外部送信しない。明示の検索依頼または画像添付と送信が必要。新規API課金検査は実行しない。

通常DB・設定・QSettingsから隔離して実画面を検証する。対象回帰、Ruff、test.batを実行し、過去の全体Qt異常の結果を今回の成功証拠へ流用しない。バックアップは `local/diagnostics/preview-settings-20260922/before/`。

## 実装内容と原因

- 接続設定のコンボボックスが長いマイク名を最小幅として要求していた。長い試験名でページ幅1180px・表示幅526px・横スクロール654pxを再現。文字数による最小幅を制限し、選択名全体はツールチップで読めるようにした。修正後は同条件でページ幅526px・横スクロール0px。上下の余白も伸縮する。
- 水色は素材やモーフ値ではなく、OpenGLの半透明描画時に完成画面のαまで下がる合成設定が原因。`grabFramebuffer()` は正常でも、Qtによるウィジェット合成で前髪・頬が水色に化けていた。RGBとαの係数を `glBlendFuncSeparate` で分け、背景の不透明性を維持した。PMX・PNG・表情の値は変更しない。FBOをQtの画面へ合成する仕組みとRGB／αの係数分離は、[Qtの公式資料](https://doc.qt.io/qt-6/qopenglwidget.html)と[OpenGL仕様のBlending節](https://registry.khronos.org/OpenGL/specs/gl/glspec30.pdf)も参照した。
- モーション選択時のプレビューは、読み込んだデータの複製だけを非ループにする。原本の待機ループ・カタログ・速度は維持。管理中だけ正面・標準倍率・全身表示にし、閉じると利用者の画角・回転・ズームを戻す。停止した後のウィンドウ再表示では再開しない。
- 未使用・利用不可のモーション、会話未割当・モーフ不足の表情を薄い文字と状態名で区別。再有効化・編集・理由確認のため選択は可能。未対応モーフも薄い文字にした。
- Web検索と画像送信は標準オン。会話メニューと詳説選択肢を撤去し、許可チェックを「設定」→「会話・音声」に移した。チェックだけでは外部送信せず、無効中の送信操作でも勝手に再有効化しない。接続先の変更でも無効設定を維持。許可設定は従来同様に起動中だけで、次回起動時はオンへ戻る。新しい設定キー・YAML・DB形式は作らない。

## 実描画の比較

同じ実PMX・標準品質・固定姿勢で、GPU画像とQt合成後の画像を比較。異常なシアン色の検出条件は R＜40、G＞180、B＞180。画素数はこの固定条件での診断で、全表情・全端末の保証ではない。

| 表情 | 修正前の異常色画素 | 修正後 | 修正前の最小α | 修正後 |
| --- | ---: | ---: | ---: | ---: |
| 通常 neutral_soft | 2,303 | 0 | 140 | 255 |
| 照れ embarrassed_soft | 9,007 | 0 | 138 | 255 |

証拠は `local/diagnostics/preview-settings-20260922/alpha-before/` と `alpha-after/`。修正後はGPU画像、ウィジェット画像とも正常で、全画素のαが255。別の100％／150％管理画面検査でも照れ表情の異常色は0画素だった。

## 検証の区分

- 実装済み：上記9本の本体ファイルの変更。新規依存・公開API・環境変数・保存形式・通常データの変更はない。
- 自動テスト済み：対象329件成功（`target-final.log`、44.00秒）。初期テスト97件、描画・UI対象137件、画像・アプリ対象55件も成功したが、件数は重複を含むため合算しない。
- 全体検査済み：最終 `test.bat` は **1126件成功・89.31秒、Ruff check成功、format check 247ファイル成功**（`test-bat-verified.log`、終了コード0）。停止後の再表示修正と古いツールチップ撤去を含む最終コードで実行した。
- Codex環境の統合確認済み：Windows実Qt・実PMXで100％と150％の表示倍率。接続設定550px／420px幅の右端、表情の一覧選択、全身モーションの選択時開始・非ループ終了・再生・途中停止・画角復帰。別の描画器やモデル読込は追加していない。通常DB・local直下YAMLは各実画面検査の前後ハッシュ一致、外部要求0。
- 実機受入待ち：利用者が普段使う画面・倍率での読みやすさと操作感。実音声の聴感、新しい実API、全GPU・全表情の網羅、長時間待機はこのUI修正の検査に含めない。

途中の失敗も保存した。`target-03.log` は追加したGPUテストの偽シェーダーが数値の代わりにMockを返した試験実装のエラー（46成功・1失敗）で、偽オブジェクトを修正して再検査した。画面を隠して再表示すると選択済みの動作を再開する欠陥も最終確認で検出（`reshow-before.log`）。初回表示だけ自動再生するよう修正し、関連17件成功（`reshow-after.log`、1.98秒）。テストを削除・無効化したり基準を緩めたりしていない。

全体バッチ初回も1126件・Ruff成功。その後の停止再表示修正を含む再検査ではpytest1126件成功、Ruff check成功だったが、format checkが1ファイルの改行を指摘した（`test-bat-final.log`）。整形し、残っていた旧メニューのツールチップも更新して上記の最終バッチを実行した。前回作業のQt内部Abortedは今回の全体検査では再現しなかったが、その根本原因を修正・特定したという意味ではない。

実画面の証拠は `native-final/`、`native-150-final/`。最後の停止再表示の追加修正も `native-reshow-final/` の100％実画面で確認し、停止後に再開しないこと、通常ファイル不変・外部要求0を再確認した。最終の古いツールチップ撤去は全体テストで検査した。150％表示の描画・レイアウトコードはこの最終版と同じ。

管理画面の画像更新12回の測定は100％で中央値7.87ms・最大11.48ms、150％で中央値10.95ms・最大13.55ms。更新周期150ms以内だった。これは固定姿勢の描画取得の短い測定で、音声同期や長時間性能の受入ではない。

## 利用者が次に行う操作

新しいAPI要求や、Codexで済ませた機能検査を繰り返す必要はない。日常の操作で見え方を確認する場合だけ、以下の順に進める。

1. 起動中のアプリを閉じ、プロジェクトの `run.bat` をダブルクリックして再起動する。通常のDBや設定は削除しない。
2. 右上「設定」→「会話・音声」→「LLM接続・マイクの設定」を開く。入力欄の右端と保存・キャンセルが見えれば正常。確認だけなら「キャンセル」で閉じる。
3. 「設定」→「表示」→「モーションを管理」を開き、一覧の別の行を選ぶ。頭から足まで見え、一度再生して待機へ戻るのが正常。「プレビュー停止」で途中停止、「閉じる」で元の画角に戻る。
4. 「表情を管理」で通常／照れを選ぶ。前髪・頬に水色の乱れがなく、薄い文字の項目を有効な項目と区別できれば正常。見るだけなら保存せず「閉じる」で戻る。
5. 検索・画像送信を止める場合だけ「設定」→「会話・音声」の許可チェックを外す。再開は同じチェックを入れる。変更はこの起動中だけ。詳しい説明は会話文で頼む。

文字やボタンの見切れ、色の乱れ、停止後の勝手な再生が残る場合は「プレビュー停止」または「閉じる」で通常画面へ戻り、画面名と操作を知らせる。スクリーンショットや通常会話の再送は必須ではない。利用者の普段の画面での操作感は実機受入待ちであり、フェーズ10／11を自動で受入完了にはしない。
