## 1. 能動的な話しかけとは

これは予定やタスクを管理する機能ではありません。利用者が有効にした場合だけ、会話がしばらく静かなときに雨衣が会話欄から短く話し始める機能です。

例えば、直前に映画の話を自然に続けていた場合は、その流れを軽く受ける一言になります。話題を終えた、触れないでと伝えた、忘れるよう求めた内容は、雨衣から再開しません。特に、直前の雨衣の発話が話題の終了または境界の確認だった会話では、雨衣から新しい発話を始めずに待機します。何も自然な続きがなければ、返事を要求しない日常的な一言だけにします。

この機能が使うものと使わないものは次のとおりです。

| 項目 | 内容 |
| --- | --- |
| 使う | 現在選択しているLLM、人格設定、開いている会話の要約と直近の会話 |
| 使わない | 保存済みの利用者記憶、予定、タスク、外部通知、外部ツール、PMX・音声素材 |
| 送信の条件 | 利用者が有効にした後、静かな時間帯外で、待機時間と最短間隔を満たしたときだけ |
| 回数 | 1回の発話につきLLMへ1要求。既定は利用者の操作後30分、次の発話まで120分以上 |
| 音声 | 「能動発話を読み上げる」をオンにした場合だけ、現在のVoiSona設定で再生 |

そのため、能動会話をオンにすると、利用者が入力していない間にも設定中のLLMプロバイダーへ上記の会話文脈が送信され、通常の利用料金が発生します。読み上げのオン／オフはLLM送信のオン／オフとは別です。止めると、新しいLLM要求と未反映の発話は止まります。

## 2. 自動確認済みの範囲

- 能動会話は既定でオフ、静かな時間帯・待機時間・最短間隔・読み上げを利用者が設定できる。有効化または復帰して保存した時点から待機時間を数える。
- 会話中、録音中、音声再生中、入力欄に下書きがある間は開始しない。
- 下書き、送信、録音開始、「音声・動作を停止」、能動会話の無効化で、返却待ちの能動発話を無効化する。プロバイダー通信が物理的に完了した場合も、その結果は履歴・画面・音声へ反映しない。
- 能動発話は通常のアシスタント発話として会話履歴へ保存し、人格・会話要約・表情・視線・動作の既存経路を使う。
- 能動発話から記憶候補を作らず、保存済み記憶や予定を自動参照しない。
- 終話または境界の確認直後は、LLMへ要求せずに待機する。終了や境界を言い換えて繰り返さない。
- UIテストのQSettingsは一時INIへ隔離し、利用者のWindows設定をテストの保存先にしない。
- 旧実LLM50ターンはMemoryService未接続だった。後続の新50ターンでは接続し、保存・訂正・削除・無効化・別会話を検査した。結果と限界は最新報告を参照。能動会話は別経路としてMockとoffscreen UIでも回帰確認し、自動検査を自然さの受入とは扱わない。

修正後の実行は生成50要求と各ターンの固定基準判定50要求、計100要求である。通常の会話DB、利用者記憶、音声、PMXは使っていない。料金はプロバイダー契約と実際の入出力トークンに依存し、この記録には金額を保存していない。当時のCodexによる読み取りもAI評価であり、人が評価した実績ではない。「違反がないことを確認した」という包括的な説明は取り消し、保存記憶を含む未評価項目と、後の実行で見つかった不具合を最新報告で区別する。

### 実LLMによる能動会話の文面確認（2026年9月22日）

現在選択中の `gpt-5.6-luna`（temperature 0.7）へ、メモリ内SQLiteの架空会話だけを送った。通常の会話DB、保存済み記憶、音声、PMXは使っていない。保存済み記憶の代わりに「午前5時に起床する」という検証用の予定をメモリ内に置き、送信プロンプトに含まれないことも確認した。

最初の5場面では、映画の続き、質問直後の散歩、文脈なしの一言はCodexの読み取りで自然と評価した一方、終話・境界の直後に内容を言い換えてしまう2件を不合格として記録した。この結果を受け、終話・境界の確認直後はLLMへ送らず待機するよう修正した。修正後の再確認は次のとおりである。

| 場面 | 結果 | 確認内容 |
| --- | --- | --- |
| 映画の余韻 | 合格 | 「エンドロールが終わっても…」と、直前の話題を短く自然に受けた。 |
| 話題を終了 | 合格 | LLM要求0件、会話欄への追加0件。 |
| 境界を示した直後 | 合格 | LLM要求0件、会話欄への追加0件。 |
| 質問が連続した後の散歩 | 合格 | 質問で返さず、散歩の景色を短く受けた。 |
| 文脈なし | 合格 | 予定・通知ではない、返答を要求しない短い一言になった。 |

構造確認では、生成した3件すべてが100文字未満、質問終端なし、予定・通知等の語なし、記憶候補なし、検証用予定のプロンプト混入なしだった。外部要求は、初回5件、端末文字コードのため同条件で読み直した5件、修正後に実際に生成した3件の合計13件である。専用Judgeとは別にCodexが実返答を読んだ評価であり、これもAI評価である。人が読んだ判定との過去の表現は訂正する。その後、利用者が能動会話を明示的に受け入れた。

## 3. 能動会話の操作資料（受入済み・再確認の依頼ではない）

### 準備

1. アプリを終了している場合は、プロジェクト直下の「run.bat」をダブルクリックして起動します。
2. 既存会話を一つ選ぶか、左側の「新しい会話」を押して会話を作ります。予定の登録や「記憶を管理」の操作は不要です。
3. 音声を試す場合も、音声設定や雨衣の声を変更せず、現在の設定のままにします。

### 文字だけの能動会話

1. 入力欄へ、例えば「最近見た映画の余韻が残ってる」と入力して送信します。
2. 左側の「能動的な話しかけ」を押します。
3. 「能動的な話しかけを有効にする」をオンにします。確認時だけ、現在時刻を含まない静かな時間帯を選び、「利用者の発言後の待機」を最小の5分、「話しかける最短間隔」を最小の15分にします。「能動発話を読み上げる」はオフのままにして「保存」を押します。この保存時点から待機時間を数えます。
4. 入力欄を空にし、マイク入力と音声再生を始めず、そのまま5分以上待ちます。
5. 正常なら、会話欄に雨衣から1〜2文の新しい発話が追加されます。予定、歯医者、会議、通知、リマインダーを根拠にした文ではなく、人格と直前の会話に合う短い一言です。音声は再生されません。

合格は、雨衣の一言が会話の流れに無理なく、閉じた話題を勝手に再開せず、返答や予定管理を強要しないことです。同じ待機中に連続して発話せず、次の発話は設定した最短間隔を過ぎるまで出ないことも確認してください。

### 読み上げありの能動会話

1. 「能動的な話しかけ」をもう一度開き、「能動発話を読み上げる」をオンにして「保存」を押します。
2. 前の能動発話から設定した最短間隔が過ぎた後、再び入力・録音・音声再生をしない状態で待ちます。
3. 正常なら、会話欄に追加された同じ文だけが現在の音声設定で読み上げられます。雨衣はその文に対応する表情・視線・動作へ移り、音声終了後は承認済みの待機姿勢へ戻ります。

合格は、通常会話の音声や古い動作が再開せず、読み上げをオンにした能動発話だけが再生されることです。

### 取消、停止、復帰

1. 状態欄が「能動会話: 考え中」の間に、入力欄へ短い下書きを書くか、「マイク入力開始」を押します。
2. 正常なら、状態欄は「能動会話: 有効（文字のみ）」または「能動会話: 有効（音声あり）」へ戻り、前の能動発話は会話欄にも音声にも出ません。通信完了後に古い文が遅れて出る場合は不合格です。
3. 読み上げ中に止める場合は、右下の「音声・動作を停止」を押します。正常なら音声・口形・動作が止まり、その文が再開しません。
4. 完全に止める場合は、「能動的な話しかけ」を開き、「能動的な話しかけを有効にする」をオフにして「保存」を押します。状態欄が「能動会話: 停止中」なら正常です。
5. 復帰する場合は同じ画面で有効にして「保存」します。保存した時点から待機時間を数え直し、その後に最短間隔も満たした場合だけ、新しい発話が始まります。

## 4. 会話品質の受入

以前の「通常アプリで新しい会話を作って架空情報を送る」手順は撤回します。「新しい会話」だけでは、通常DB・保存記憶・設定から隔離できません。

[A〜Cの受入記録](phase9-abc-acceptance_ja.md) に、入力文、ボタン、期待する反応、合否条件、停止・復帰方法を保持しています。12入力の確認は終了しており、再実行は不要です。通常利用は `run.bat` から行い、通常データを編集・削除したり検証データを移したりする必要はありません。

## 5. 受入状態・制約と問題の報告方法

- 実装済み: 能動会話のLLM生成、任意の読み上げ、取消、既定オフの設定。
- 自動テスト: 以前の918件成功、927件成功＋Ruff失敗は過去の記録。後続修正後の最終`test.bat`は969件成功、Ruff check・書式検査成功。
- Codex環境の統合確認: 隔離SQLiteと実MemoryServiceで50ターン比較、実Backendと記憶画面の操作を自動確認。別途、実ウィンドウと現在の音声設定・PMXへ保存済み実返答を再生して、表示・読み上げ状態・停止を確認。音の主観品質を合格にはしていない。
- 利用者実機受入済み: 能動会話Dの明示的な受入と、A〜Cの12入力について良好との報告をもって、現行採用範囲のフェーズ9を終了する。
- 保持する制約: 新50ターンのCodex読み取りの懸念10件、Judge未受理22件・判定保留1件は合格へ付け替えない。全ての表現・モデル・長期利用での品質を保証するものではない。詳細は受入記録を参照する。
- 未解消: プロバイダー通信そのものを途中で中止できるかは各プロバイダーの契約に依存します。本アプリは完了後の保存・表示・読み上げを必ず無効化します。

不合格だった場合は、能動会話をオフにしたまま、能動会話の有効／読み上げの有効、静かな時間帯、待機時間、最短間隔、下書き・録音・音声のどの操作をしたか、表示または再生された一言だけを共有してください。会話全文、予定、秘密情報は共有しないでください。
