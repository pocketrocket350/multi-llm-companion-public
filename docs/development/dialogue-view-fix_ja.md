# セリフの形式漏れ・回転・全身表示の修正

2026-09-25。利用者の画像と追加指示に基づく修正。前回の左右90度の解釈を左右180度へ訂正する。

## 修正前の範囲と合否条件

1. `**speech**: "…" **emotion**: …` のような形式漏れを本文・音声・永続会話へ流さない。確定したセリフだけを回収できる場合は一度だけ使い、不正な記憶更新・動作は採用しない。判別できなければ既存の形式エラーで止める。正しいJSON、普通の文章、取消の挙動を維持する。
2. 標準の手動回転を正面から左右180度にする。設定をオンにした場合はその境界を越えて繰り返し回転できる。上下へは傾けない。既存の設定キーを使う。
3. 全身アイコンの四隅の囲いを外し、バストアップと同じ線・色の人物だけにそろえる。
4. 全身表示で縮小できる下限を、表示領域の高さに全身が収まる標準倍率にする。小さくしたバストアップから切り替えた場合にも適用する。拡大と背景の連動、原本・姿勢・表情・モーションは維持する。

追加依存・外部送信・APIパラメーター・DBスキーマ・保存形式を変更しない。通常データは書き換えず、検査は分離したDB・設定で行う。既存の不正な発言を含む履歴は自動削除しない。

変更前のコピーは `local/diagnostics/dialogue-view-fix-20260925/before/`。修正前の再現、対象テスト、Ruff、`test.bat`、隔離した実PMX画面で確認する。有料の実API評価は今回実行しない。

## 今回実装した内容と原因

セリフの異常は、LLMが正規のJSONではなく `**speech**: "…" **emotion**: …` と返した場合に、解析失敗の代替処理が全文をセリフとして採用していたため。ストリーム中は保留できていたが、最後の保存・読み上げ時にこの形式を止められていなかった。

- 既知の制御項目が並ぶMarkdown応答から、完全な引用文字列のセリフが一つだけ判別できる場合に限り回収する。前置きと重複して読まず、表情・動作・記憶更新は採用しない。引用が閉じていない、セリフが数値、セリフ項目が重複する場合は保存・読み上げを止める。
- 同じ形式で既に保存されていた雨衣の発言は、表示とLLMへの会話文脈に使う際にセリフだけを取り出す。利用者の文章やDB原本を書き換えない。正規JSONと普通の文章の既存経路は維持する。
- 手動回転の標準を正面から左右180度に変更。設定の「モデルを横方向へ続けて回転できるようにする」をオンにすると、端で止まらず何周でも回転できる。同じ保存キーを使い、上下へ傾けない。
- 全身アイコンの四隅の囲いを外し、バストアップと同じ濃紺の線で人物を描く。ボタンの位置・枠・操作は共通のまま。
- 全身表示の最小倍率を1.0（表示領域の高さに全身が収まる標準倍率）にする。ホイールでさらに縮小しても止まる。小さくしたバストアップから切り替えた場合も適用し、ウィンドウを小さくするとその高さに合わせる。拡大、背景との連動、一時プレビュー終了後の元の表示への復帰は維持する。

## 利用者が次に行う操作

以下は使い方の案内。上記の自動テストや隔離確認を繰り返していただく必要はない。

1. 通常アプリを閉じ、プロジェクトの `run.bat` を開いて再起動する。今回のコードが読み込まれる。
2. モデル右上の人物アイコンで全身／バストアップを切り替える。両方とも同じ濃紺の人物図形になり、全身への切替用図形の四隅の囲いはなくなる。
3. 全身表示でモデル上のホイールを縮小側へ回すと、頭から足先が表示領域の高さに収まる大きさで止まる。拡大は従来どおり可能。ウィンドウの高さを変えれば収まる大きさも追随する。
4. 左右にドラッグすると、標準では正面から左右180度まで回る。続けて回したい場合だけ、右上の歯車→「表示」→「モデルを横方向へ続けて回転できるようにする」をオンにする。オフに戻すと左右180度で止まる。「雨衣を正面に戻す」で元の向きと倍率に戻せる。
5. 普段どおり会話する。今回の画像と同じ形式で保存された発言は、履歴でもセリフだけに直して表示される。新しい返答では内部項目を読み上げない。判別不能な場合は返答形式のエラーで止まり、次の普通の入力へ戻れる。
6. 実際の会話で内部項目が再び見える・読まれる場合は「音声・動作を停止」を押し、画面と直前の入力文を知らせていただく。視覚操作だけ戻したい場合は正面へ戻すか人物アイコンを押す。回転・アイコン・縮小限界の実装確認は済んでおり、利用者に残る判断は意図した見た目・操作感になっているかである。
