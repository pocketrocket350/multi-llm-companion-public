# 入力欄のIMEと画像添付（2026-09-24）

**現行の追加仕様（2026-09-29）**：利用者指定によりブラウザの画像データ・画像URLのドロップにも対応し、送信した画像の縮小コピーを会話履歴に保存・表示する。会話削除でコピーも削除する。URLからの画像取得は発生するが、AIへの共有は送信ボタン時だけ。[現在の実装・検査・操作手順](image-history-drop_ja.md)。以下の「外部URLを受け付けない」「履歴の保存内容を維持」は9月24日時点の履歴で、現在の制限ではない。IME・添付欄下のサムネイル・×・コピーとしてのドロップは維持している。

## 今回の変更

- 会話入力へフォーカスしたとき、選択中のWindows IMEをオンにする。入力中に手動でオフにした場合は、そのまま維持する。キーボード配列・入力言語の切替は行わない。
- 添付画像は入力欄下のプラスの右へ表示する。ファイル名・画像寸法・注意書きは添付欄から除き、サムネイル右上の×で外せるようにする。操作名はツールチップとアクセシブル名で維持する。
- 入力欄・主画面へローカルのPNG/JPEG/WebPを1枚ドロップできる。プラスで選ぶ場合と同じ画像検査・メタデータ除去を通す。ドロップはコピーとして受け付け、原本の移動を要求しない。
- 選択・ドロップだけでは送信しない。既存の質問入力と送信操作、許可設定、取消・遅着結果破棄、履歴の保存内容は維持する。

新しい依存、設定、DB、送信先は追加していない。外部URLや複数ファイル、処理中の添付は受け付けない。エクスプローラー上の画像ファイルが対象で、ブラウザー上の画像URLを直接取得する機能ではない。

IMEには既存のctypesからWindows標準APIを呼ぶ小さな専用処理を使う。Qtのフォーカス処理後、まだ同じ入力欄が編集可能な場合だけ適用する。取得した入力コンテキストは必ず解放する。根拠はMicrosoftの[ImmGetContext](https://learn.microsoft.com/en-us/windows/win32/api/immdev/nf-immdev-immgetcontext)、[ImmSetOpenStatus](https://learn.microsoft.com/en-us/windows/win32/api/immdev/nf-immdev-immsetopenstatus)、[ImmReleaseContext](https://learn.microsoft.com/en-us/windows/win32/api/immdev/nf-immdev-immreleasecontext)と、Qtの[フォーカス処理](https://doc.qt.io/qt-6/qwidget.html#focusInEvent)。変換中のEnterが送信へ流れないことも回帰検査する。

## 普段の使い方

1. 開いているアプリを閉じ、プロジェクトフォルダーの `run.bat` をダブルクリックして再起動する。通常の履歴・設定の削除は不要。
2. 右下の会話入力欄をクリックすると、選択中のIMEがオンになる。英数字で入力したければ、入力中に通常どおりIMEをオフにできる。別の場所をクリックして入力欄へ戻ると、再びオンになる。
3. 入力欄下の **＋** で画像を1枚選ぶか、エクスプローラーの画像ファイルを入力欄へドラッグ＆ドロップする。同じ下段のプラスの右に小さな画像が出る。ファイル名や注意書きは出ない。
4. 画像右上の **×** を押すと添付だけを外せる。本文は残る。ここまでの操作ではAPIを呼ばない。
5. 画像について話すときは質問を入力し、入力欄右の三角矢印で送信する。通常のAPI料金が発生する。送信中は入力欄上の「画像・返答を取消」、音声中は「音声・動作を停止」で止め、終了待ち表示が消えれば次の会話へ戻れる。

Codexで済ませた検査一式を繰り返す必要はない。普段のIMEで確定だけのEnterが送信になる、サムネイル・×が見切れる、画像ファイルを置いても添付されない場合は送信を止め、操作と画面倍率を知らせる。画像は×で解除できる。
