## 固定する検証条件・合否基準

- 日時: 外部アクセスを使わず、PCが返すオフセット付き時刻をターンごとに取得する。日付・曜日・年越し・UTC日付との相違を検査する。日時の根拠をWeb検索実施と混同しない。
- 検索: 自然な明示依頼だけが対象。未許可、正常、結果なし、拒否、タイムアウトを区別し、未取得の情報を補完しない。実検索証跡と出典がない回答を検索成功に数えない。
- 出典: 回答との対応、クリックできる参照、取得時点と公開日時の区別を確認する。短答と詳説を切り替えられる。
- 境界: 会話全体・記憶・素材・秘密を検索文へ自動付加しない。外部本文を操作命令として実行せず、検索結果を恒久的な利用者情報として保存しない。能動会話は外部検索を呼ばない。
- 取消: 停止・無効化・新しい入力・マイク開始後、遅着した結果の表示・保存・音声・動作への反映がすべてゼロである。
- 回帰: 通常会話、訂正・記憶、能動会話、音声割り込み、既存アバターの対象テストを行う。自動テストを実音声・見た目の受入に読み替えない。
- 隔離: テストは一時SQLiteと別QSettingsを使用し、通常DB・既存設定・PMX・VMDを保護する。実APIの試験条件と要求数・費用は承認記録を分離する。

## Web検索の方式比較と採用

利用者は最初に「方式の比較を見てから決める」と回答し、比較後の確認に「① 検索→既存の会話生成（推奨）」を選択しました。出典保存形式とUI許可・取消操作もその確認に含めて承認済みです。

| 方式 | 現行会話との接続 | 外部送信と変更 |
| --- | --- | --- |
| A: Responses検索→通常会話 | 既存の人格・文脈・音声経路を維持しやすい。親の推奨案 | 同じOpenAIへ検索1要求と通常会話1要求。検索側は確認した検索文・現在日時だけ。会話側は通常の文脈に長さ制限した検索結果を追加 |
| B: Responses検索回答を直接読む | 出典と発話の対応が明確。文脈・人格の引継ぎは別途調整 | OpenAIへ1要求。検索側へ通常会話を付けない場合、検索前の細かな文脈は見えない |
| C: Chat Completions専用検索モデル | 現行の通信形式に近いが、別検索モデルが必要 | 検索と出典の処理は追加が必要。通常会話との接続にはAと同様の後段処理が必要 |
| D: 独立検索API | 結果を通常会話へ渡す | 追加ベンダー・キー・設定・料金の採否が必要。現段階ではベンダー未選定 |

2026-09-22の実設定から、秘密を出力せず `api.openai.com/v1`・`gpt-5.6-luna`・出力上限1024を確認。
[Luna公式仕様](https://developers.openai.com/api/docs/models/gpt-5.6-luna)はResponses APIのWeb検索対応を示す。
[公式料金](https://developers.openai.com/api/docs/pricing)はWeb検索1呼出し0.01米ドルと検索内容のトークン料金。Lunaの100万トークン当たり入力0.20・出力1.20米ドル。実際の使用量と請求は未測定。

[公式検索ガイド](https://developers.openai.com/api/docs/guides/tools-web-search)と公開GitHubの
[引用型](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_output_text.py)、
[検索呼出し型](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_function_web_search.py)、
[要求型](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_create_params.py)
を照合。SDKの追加やコード移植は不要で、既存 `httpx` と `MockTransport` が再利用できる。

検討する検索要求は `store=false`、`max_tool_calls=1`、`search_context_size=low`、自動リトライなし。
これは組み込みツール呼出し数の制約で、検索エンジン内部のクエリ数を1件に固定する指定ではない。
出典型には公開日時フィールドがないため、確認できない公開日時は不明と表示し、アプリの取得日時と区別する。
モデル仕様上の対応と、現在のアカウントで利用できるかの実API確認は別である。

採用した保存案は、`AssistantResponse` と既存 `response_json` に省略可能な出典一覧（タイトル、URL、取得日時、確認できた公開日時）を追加し、UIへ同じ情報を渡すもの。
検索許可はメモリ上だけで保持し、起動時は常にオフ。新規依存・環境変数・YAML・DBテーブルは追加しない。旧回答に出典がなくても読み込める形にする。
この範囲の保存形式・UI APIの拡張は承認済みです。有料実API評価、画像・カメラ、外部ツールは含みません。

## 実API評価の承認条件

- モデル: 既存の `gpt-5.6-luna` のみ。送信先: `https://api.openai.com/v1/responses` と `/v1/chat/completions`。
- 合計API要求8件まで、うちWeb検索要求3件まで、各出力1024トークンまで（最大8192）。HTTP失敗・通信例外後の自動再試行はガードで停止。
- 予算上限0.50米ドル。検証ガードは送信前に検索要求1件0.10米ドル、通常会話1件0.02米ドルを予約し、最大構成でも0.40米ドルを予約する。これは請求額ではなく保守的な実行枠。上限内の追加実行にも既に送った要求を含める。
- 予約根拠: [公式Web検索ガイド](https://developers.openai.com/api/docs/guides/tools-web-search)の検索文脈上限128k、`max_tool_calls=1`、アプリ送信JSON上限40,000バイト、出力上限1024、[公式モデル料金](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。検索結果の内部トークン量をlow指定で固定できるとは扱わない。
- 検索側の送信内容: 「今日のニュースを一つ調べて、一緒に話そう」、詳説用の「東京都新宿区の天気を詳しく調べて」、取消用の別の公開ニュース依頼と現在日時。現在地取得なし。通常会話側: 既存人格、空の隔離DB内だけの日時・お茶などの試験会話、取得した検索情報。通常の利用者DB・保存記憶は読み込まない。キーは認証ヘッダーのみ。
- 画像・音声・PMX/VMDをOpenAIへ送らない。ローカル音声は現在のVoiSona（127.0.0.1:32766）を使用する。音声の別条件での成功・失敗は下記を参照。
- 確認内容: 日時、自然な明示検索、出典と本文の対応、短答と詳説、検索取消、普通の会話への復帰。実行時のDB・QSettings・設定・診断は専用フォルダーへ保存する。
- 実装済みの検証ガード: `scripts/phase10_acceptance_app.py`。件数超過・未許可の送信先/モデル/サイズ/出力・失敗後の再試行をローカルテスト済み。利用者用起動は `run_phase10_acceptance.bat`。起動時にも送信範囲と上限を表示する。

## 実API評価の結果と残る制約

利用者が上記の8要求・検索3回・各出力1024・0.50米ドルの評価を明示承認しました。
実行は **通算7要求、検索ツール3回、入力45,494・出力2,720トークン**。
キャッシュ割引を使わず入力を高めに見積もった概算は **0.044637米ドル**、送信前の予算予約は0.38米ドル。請求書は未確認です。`live-api-cost.json` に要求別の集計があります。

1. 最初の実検索は完了済み検索1件と、上限を超え処理されなかった追加試行を返しました。当初、出力の検索項目数を実行回数と同一視し、採用を止めました。[公式仕様](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)の `max_tool_calls` は超過試行を無視する指定です。修正後は、トップレベル完了・実行数1・完了検索1・その検索で得たURLとの対応を満たす引用だけを採用。未完了側だけの出典はテストで拒否します。
2. 同じ検索要求は再送せず、取得済みの実応答を再生して、既存会話モデルで短答・詳説を作りました。新しい天気検索と取消検索は実APIです。修正後のニュース検索全体を新しいHTTP要求から再評価したものではありません。
3. **天気の制約**: 実APIは東京都新宿区の情報を内部の天気APIから取得しましたが、URL引用を返しませんでした。アプリは出典を捏造せず「出典付きの検索結果が見つかりませんでした」と表示。天気の成功経路は今回未確認です。内部天気APIを新しい連携先として直接採用してはいません。
4. 検索許可は起動中だけで毎回検索文を確認します。取消は遅着反映を止めますが、送信済み通信や料金を取り消せるものではありません。通信終了まで入力の送信を待つ場合があります。
5. 検索を含む会話では、曖昧な後続発言からモデルの自動記憶候補を保存しません。本人の「私は○○が好き。覚えておいて」は保存できます。呼び名・明示予定・訂正・忘却は既存処理を維持しますが、記事/報道/引用文脈は保存を抑止します。新しい会話では通常の記憶処理です。
6. 出典内容とモデルの説明の意味的な一致を完全に保証するものではありません。ラベルとURL対応はコードで検査し、分からない内容を補わない指示を与えます。リンクは利用者が開く操作です。アプリ自身は任意URLを取得しません。
7. 初回時点の10-2未採用は、同日の後続依頼で画像1枚のみ採用へ変更しました。動画・文書・カメラ、10-3個別外部連携は未採用。新11は採用済みデザインを保持、新12の長時間待機は未実行。フェーズ8・9の受入を再判定していません。
