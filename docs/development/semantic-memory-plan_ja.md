# 会話の意味による記憶：実装・評価計画

2026-09-25。実装前に記録した計画。同日、利用者が「この方式で承認する」と回答し、公開回答データの拡張を承認済み。有料の実API評価は別途承認が必要。

## 目的と採用案

特定の言い回しを記憶の必須条件にせず、通常の返答を生成する同じLLM呼び出しで、本人の発言と直近の会話から記憶の追加・訂正・削除を判断する。自然な受け答えを優先し、記憶のたびに確認ダイアログや保存報告を出さない。既存の記憶管理・自動承認設定を使う。

返答に省略可能な `memory_updates` を追加する案とする。各項目は操作、内容、分類、今回の本人発言からの根拠引用、訂正・削除対象のIDと旧内容を持つ。旧履歴と従来の文字列候補は読み込める。モデルの判断が空配列なら、固定語句による補完で覆さない。秘密情報・根拠不一致・古い対象への更新はアプリでも拒否する。

実装時の決定：更新案は今回の保存判断だけに使い、通常の会話履歴では空配列にする。根拠引用や削除対象の旧内容を回答メタデータとして残さず、履歴の再読込から更新を再実行しない。検査用の架空会話に限り、評価側で更新案を記録する。

検索や画像の外部情報は本人の事実にしない。検索後も、本人が新たに語った情報は通常の記憶判断に戻す。能動発話からは記憶を作らない。会話の理解と参照用に、承認済みの記憶を上限付きで同じ会話接続に渡す。新しい検索先や画像解析側へ記憶を渡さない。

依存関係・環境変数・設定形式・DBテーブル・API要求回数は増やさない。返答データに任意項目を追加するため、AGENTS.md第2節・依頼第4節に基づく事前承認を求める。有料の実API評価は別の承認枠とする。

## 合否条件

1. 趣味・仕事・生活習慣・継続中の目標・本人の大切な経験・会話上の希望を、固定キーワードがなくても扱う。
2. 「走る方」などの短い返答を直前の問いと結び付ける。曖昧な相づちだけから新しい属性を作らない。
3. 訂正は同じ記憶を更新し、旧情報を残して二重に参照しない。同じ情報の言い換えを増やさない。
4. 記憶の拒否・明示的な削除・無効化・自動承認オフを守る。
5. 引用・架空の人物・第三者の話・記事や画像の内容を利用者本人の事実へ変換しない。一時的な気分や推測した親密さを恒久保存しない。
6. 停止・新しい会話・記憶管理での変更後に遅れてきた結果を反映しない。
7. 再起動・新しい会話でも、承認済みの記憶を話題に合わせて自然に参照できる。
8. 不正な任意メタデータで通常の返答を失わず、メタデータを読み上げない。

自動テストは保存境界・互換性・制御経路を検証する。LLMの意味理解の成否はモックでは証明せず、承認後の実API評価で別途判定する。実アプリ検査のDB・設定・QSettingsは通常環境から分離する。最終的な自然さは利用者受入待ちとして報告する。

実装・評価の結果と利用者向け操作は [意味による記憶の実装記録](semantic-memory_ja.md) にまとめる。
