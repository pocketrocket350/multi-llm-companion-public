# 能動発話への割り込み時の送信保留修正（2026-10-07）

既存フェーズ7・9・10の品質強化。通常会話の全文待ち修正を保持した上で、取消済み能動発話の通信終了を待たずに新入力を送信できるようにした。実LLM・実音声・実マイク・実PMXの性能と利用者受入は未確認。フェーズ12の原因未特定・品質合格保留と反復試験打切りを維持し、フェーズ13には移行していない。

## 経路と最小修正

修正前は、UIが旧能動threadの終了まで入力を保留し、Serviceも同じ送信ロックを保持していた。Providerの応答・usageはインスタンス共有だった。

- 能動要求には同じProviderクラス・接続条件のコピーを使い、要求結果の状態を分離する。現行のOpenAI/Mockは要求中の結果を属性代入で更新し、本番OpenAIは要求ごとにHTTP clientを作る。この前提は別Providerを追加するときに再確認する。
- 能動要求の送信ロック所有者をprivate tokenで管理する。取消時は能動要求の所有だけを解放し、旧finallyは所有が一致するときだけ解放する。通常要求が持つロックは解除しない。
- 世代検査・保存・UI応答の組立を同じstate lock区間で確定する。確定前の取消・世代不一致ではProvider結果を採用せず、保存・表情・記憶へ進めない。確定済みの過去応答を後から削除する動作は追加していない。
- Workerの取消Eventで、開始前・Backend準備・Service登録の間の取消も止める。既存の公開generateメソッドの引数は変更せず、private受付へ取消と期待世代を渡す。
- UIは旧thread/workerの参照を実終了まで保持したまま通常送信を続ける。旧終了による保留再送は削除し、重複送信を防ぐ。旧要求が残る間の能動タイマー再発火、履歴・設定操作、画面終了の既存ガードは維持する。

旧HTTP自体は中断していない。同時に残る能動要求はUIの単一threadガードで1件に制限し、返却後に取消済み結果を破棄して回収する。新しい要求を旧通信終了に連動させない。Qt並行検査で、旧workerが保持していたQThread参照が通常worker回収後に無効となる状態を再現したため、能動workerの終了時は存続中のGUI threadを取得して戻す。

## 検査・保護・限界

直接関連22件成功。新規送信と旧HTTPの重複、旧finally・取消反復による新ロックの不正解放防止、旧HTTPエラー・不正JSONからの結果分離、開始前取消3段階、DTO組立の排他、旧/新両方の終了順序、closeとnative後始末までの参照保持を検査した。

全体`test.bat`は既存`.test-tmp`削除のWinError5で失敗（1353成功・445準備エラー・445警告）。権限変更や強制削除はせず、原本ログを保持した。同じ全件を新しい隔離basetempで実行し、1798件成功・274.65秒。Ruff check成功。ルートformatは`.motion-audit-tmp`アクセス拒否で失敗として保持し、製品/検査/補助179ファイル、およびその一時領域を除く304ファイルは別に書式確認した。元の失敗を全体合格に置き換えない。

計測は30秒/ケース・45分/系列の独立期限とSTOPを備え、結果をケースごとに保存した。修正前157.391秒、修正後143.282秒、いずれも正常終了・worker回収済み。準備のusage期待値誤り、GUI検査の停止、追加検査の人工title不足、権限診断失敗は別記録し、成功に混ぜていない。

通常DB・設定・人格・QSettingsの保護照合は一致。外部HTTP・実マイク・実音声は0、PMX/VMD未使用。依存・設定/保存形式・DBスキーマ・公開APIは変更していない。Mock値を実音声の性能合格にしない。実機の音・見た目、実APIの遅延/料金/エラー時の利用者受入は未確認。

利用者の検査操作は不要。次に普段のアプリを起動すると反映される。旧通信が残る間の画面終了は従来どおり拒否され、終了を待って閉じられる。別の通常アプリやフェーズ12の試験を停止・再起動していない。計画2の対象だった通常会話と割り込みの最小修正はMock比較済みで、計画3の人工記憶による連続性検証には今回は着手していない。
