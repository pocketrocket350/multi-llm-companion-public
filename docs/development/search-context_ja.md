## 原因と今回の差分

編集前の範囲・合否条件は `local/diagnostics/search-context-20260929/plan.md`。既存変更を含む編集前13ファイルを同ディレクトリの `before/` に保存した。今回分の差分・ハッシュ一覧は `changes.diff` / `changes.json`。

1. 画像の3文は検索依頼と判定されても、その発言に地域を再記入しないと `_send_message` が地域不足として検索を飛ばし、通常LLMへ戻っていた。直近の同じ天気の会話から地域と同月の明示済み期限を引き継ぐ。「東京」「9月28日まで」を毎回言い直す必要をなくす。新しい地域・日付を優先し、話題変更・曖昧な複数地域・新会話を越えて補わない。全履歴や保存記憶を検索APIへ送る変更ではない。
2. 「今年の降水量」「例年」が観測資料向けの分岐に含まれず、検索への指示が予報向けになっていた。利用者画像の3文を観測値・同じ期間の比較へ接続した。
3. 最初の承認済み実APIでは、検索開始後に `incomplete / max_output_tokens` となり、出力884トークンがすべて推論で、本文がなかった。既定推論のままの1,024上限では本文まで到達しなかったことを、この要求について確認した。画像の過去の空本文応答そのものは取得しておらず、過去の全失敗を同じ原因と断定しない。
4. OpenAI公式接続の `gpt-6-luna` に限り、会話では `reasoning_effort=none`、検索では `reasoning.effort=none` を明示した。モデル・出力上限・設定形式を変えず、短い会話の枠で本文を生成する。通常会話、検索後・画像後の会話生成にも適用する。画像解析要求そのもの、他モデル・互換接続は変更しない。`none` 指定でも今回の検索usageには107推論トークンがあり、推論トークンが必ず0になるという保証ではない。
5. 検索開始後の出力上限終了は、出典なしの完了と区別する。「調べ始めたんだけど、途中で処理の上限に達して、検索を最後まで終えられなかったよ。今は確かな結果を伝えられないんだ。」という最終返答を既存の履歴・任意の音声経路へ渡す。追加LLM・自動再試行は行わず、途中の本文・出典を採用しない。使用量は今回の検索分だけで、前の会話分を二重加算しない。接続・認証などの重大な失敗は従来どおり明示する。
6. 出典が得られない検索完了のあと、説明文の生成が空になった場合も、確認済みの検索状態を短いセリフで返す。空本文を専用の内部例外で区別し、使用量を保持する。通常会話・出典あり生成の空本文を「資料なし」に置き換えることはしない。
7. Workerから既存の取消コールバックを常に伝播し、サービス開始前の取消でも保留検索を破棄する。取消・新規入力・録音・許可無効化のあとに古い検索や音声を再開しない。

公式資料（同日参照）：[GPT-6 Lunaの推論指定](https://developers.openai.com/api/docs/models/gpt-6-luna)、[本文前の出力上限終了](https://developers.openai.com/api/docs/guides/reasoning)、[Web検索の推論と取得](https://developers.openai.com/api/docs/guides/tools-web-search)。依存・公開API・環境変数名・DBスキーマ・保存形式・QSettingsキーは変更していない。描画、PMX/VMD、表情、口パク、ボイス、人格の保存設定を変更していない。
