# 曲名の途中で読み上げが止まる問題の修正

2026-09-24。利用者が提示した「しぐれういさん」の説明が、楽曲「粛聖」の直後で止まり、画面が「読み上げ中」のままになる問題に対応した。提示された本文を検査用に再現し、通常の会話DBから本文を取り出していない。

## 変更内容と根拠

文分割が曲名の `!!` を別々の文末として扱い、`!` だけの音声片をVoiSona Talkへ送っていた。直近の既存診断ログでは第0・1片が再生され、第2片の合成は `failed` になり、後続片の合成は完了していた。失敗を終了状態として扱わず約159秒以上照会していたため、後続の再生が止まった。製品の合成待ち上限は180秒。

- 引用内の曲名を途中で区切らず、記号だけの断片を合成へ送らない。提示本文は4文になり、表示本文・保存本文の語を変えない。
- VoiSonaの明示的な失敗・取消を直ちに終了扱いにし、再生と口形を停止する。失敗した発話への遅着片は捨て、新たな明示発話で復帰できるようにする。
- 非同期の合成失敗を会話欄のエラー表示へ反映する。失敗後に連続録音を自動開始しない。同じ失敗をタイマーごとに再表示しない。

新規依存・公開API・設定形式・保存形式の変更はない。前回の再起動後の設定保持は維持した。通常のDB・設定・原本PMX/VMD・人格・採用モーション・音声設定は変更していない。

## 失敗・未確認事項

初回の隔離アプリはCodexの制限ユーザーで動作した。Pythonが作る一時フォルダーへ、通常ユーザーのVoiSonaが書き込めず、普通の文も発音解析完了後に失敗した。同じ短文を通常ユーザー権限で合成するとWAVを作成でき、全文4文も合成できた。これは検査環境側の別問題であり、利用者の曲名での中断原因と混同しない。通常アプリの権限や保存場所を変更する修正は加えていない。

また、設定の `voice_name` は `TanakaSan` のままだが、現在のローカルAPI一覧には `ui_ja_JP` しか返らない。既存実装は指定した声が見つからないと一覧先頭を使うため、成功した無音の合成検査の実声は雨衣だった。**Tanaka Sanでの成功、音を聞いての全文確認、利用者実機受入は未確認**。音声の希望は利用者へ確認中であり、この修正で雨衣への設定変更・採用変更は行っていない。

## 利用者が次に行う操作

修正を読み込むため、アプリの再起動が必要。

1. 読み上げが止まったままなら、会話入力欄の右上にある「音声・動作を停止」を押す。
2. アプリを右上の「×」で閉じ、プロジェクトの `run.bat` をダブルクリックする。
3. 普段どおり会話する。今回の自動検査や有料LLM要求を、確認のためだけに繰り返す必要はない。

正常時は記号を含む作品名でも後続の文を読み進め、読み終えると「読み上げ中」が消え、口形が待機へ戻る。音声合成側が失敗した場合は「読み上げに失敗しました。返答の本文は会話欄で確認できます。」を表示し、失敗した続きは勝手に再開しない。本文はそのまま読める。

再び無音で「読み上げ中」が残る、停止後に古い声が再開する、次の会話でも復帰しない場合は「音声・動作を停止」を押して閉じる。その場合は止まった短い箇所と、エラー表示の有無を知らせる。会話履歴全体や秘密情報の提出は不要。
