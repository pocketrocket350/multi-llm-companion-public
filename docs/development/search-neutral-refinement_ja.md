# Web検索の確認撤去と標準の目元

2026-09-22。利用者の「ダイアログは不要」「公式パッケージを参考にちょっとジト目」の追加依頼に対応。以前の「画像だけ撤去しWeb確認を維持」という判断を訂正する。

## 変更

- Webの許可・検索文確認の別ダイアログを撤去。「調べて」と書いて送信する操作を今回の検索の許可とし、通常の会話・入力だけでは検索しない。送信先・費用・送信範囲は検索入力時だけ入力欄近くへ表示。短答が既定で、詳説は会話メニューか「詳しく」という依頼。天気の地域は同じ画面内で明示指定する。初期許可オフ、取消、無効化、秘密情報検査、文字数上限を保持。
- 既存の `neutral_soft` に、実在する `じと目` を0.30追加。従来の `Fun` 0.20を保持し、neutralの候補巡回だけを標準1件に固定する。候補プリセット自体と他感情の対応を削除しない。
- 起動時・停止後にも基礎表情を既存の表情層へ適用する。会話命令が解除されたとき、古い視線・動作・発話を復活させず、基礎モーフだけに戻る。動きオフでは姿勢を止めつつ、顔だけは簡易描画と同じように更新する。privateな画面内部処理を追加し、公開API・設定形式・DB形式・依存関係は変更しない。設定の表情確認を終了したときは、従来どおり会話側の表情を再表示する場合がある。
- 提供されたパッケージ画像は見た目の参照にだけ使用。原本PMX/VMD、表情の原本モーフ、音声、視線、姿勢、他感情を変更しない。

編集前条件と生の証拠は `local/diagnostics/search-neutral-20260922/`。評価DB・設定・QSettingsはその配下へ分離し、HTTP外部送信を禁止。今回の有料API利用はゼロ。

### 失敗と診断

- 最初の詳説テスト2件は、詳説の指示先を検索APIと誤認して失敗。既存設計どおり返答生成への指示を検査するよう修正し、18件成功。返答の短答/詳説基準は緩めていない。
- 初回のQt対象実行が検索失敗後の復帰検査で停止し、40秒のスタック出力後に中断。`QApplication.processEvents()` 内で止まった記録で、原因は未特定。対象単独の再実行は成功したが、この停止を解消扱いにしない。
- UIをまとめた検査でQt Abort、全体の再検査でQtのaccess violationも発生（`ui-target.log`、`test-bat-final.log`）。停止位置は前者が会話worker終了付近、後者がPMX表示テストのイベント処理中で、同じ原因とは未確定。標準出力も残した限定診断はUI・検索の81件成功（`ui-diagnostic.log`）。これらの異常終了記録は全体テストが成功しても残す。
- 最初の `test.bat` は1110件成功・追加1件失敗。動きオフではMixerが表情も固定していたため、標準表情へ戻れなかった。姿勢を固定したまま表情を更新するよう修正し、PMX/GPU/CPU/Mixerの対象148件が成功した（`avatar-target-03.log`）。
- 最初の表情比較は非同期の姿勢生成完了前に撮影していた。完了を待つ撮影へ修正。GPUの頂点モーフ欠落を一時疑ったが、表情を含む材質は既存のCPU処理へ分配されるため反証された。不要だったGPU処理変更は撤回。テストも実際のCPU/GPU混在経路と頂点一致を検査している。
- 前髪のシアン色の線は以前からの制約として残る。今回の目元の好みは利用者実機受入待ち。

1. アプリを閉じ、通常の `run.bat` で再起動する。起動した雨衣の目元が少し落ち着いた印象になっているかを見る。この操作にLLM料金はかからない。
2. 次に検索を使うとき「今日の世界のニュースを一つ調べて、一緒に話そう」と送る。別ダイアログなしで始まり、入力欄の上に処理表示と「検索・返答を取消」が出る。検索・会話の通常料金はかかる。Codexが済ませた取消試験の一式を繰り返す必要はない。
