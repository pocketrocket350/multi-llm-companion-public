# 会話の意味による記憶：実装と確認

2026-09-25。利用者が方式と追加評価を承認した範囲の記録。[事前の採用案・合否条件](semantic-memory-plan_ja.md)。

## 変更したこと

通常の返答を作るLLMが、今回の本人発言・直近の会話・承認済みの記憶から、追加・訂正・削除・変更なしを一緒に判断する。「好き」「趣味」「覚えて」などの語句を新形式の保存条件にしない。直前に二択で聞かれた「走る方だよ。」のような返答も、何への答えかを含めた記憶に整理する。

本人の好み、活動、生活習慣、仕事、家族、継続中の目標、大切な経験、呼び方・話題の希望を対象とする。毎回の保存報告や確認画面は追加しない。既存の「記憶を管理」で内容の確認・訂正・削除と自動承認の切替ができる。

返答の省略可能な `memory_updates` に更新案と本人発言の引用を持たせる。アプリは引用が今回の発言にあること、訂正先のID・旧内容が生成開始時と変わっていないこと、秘密情報などがないことを確認して既存の保存処理へ渡す。記憶管理・無効化・停止・会話切替後の古い返答による反映を防ぐ。更新案は通常の会話履歴に残さず、履歴を開いて再実行することもない。

検索・画像解析の結果や能動発話からは記憶を作らない。検索した後でも、通常会話に戻って本人が新たに語ったことは判断する。第三者の話・架空の設定・引用・一時的な気分・推測した恋人関係を本人の恒久的な事実にしない。「覚えないで」、明示的な忘却、記憶の無効化、自動承認オフを維持する。

LLMの送信先と要求回数、依存関係、環境変数、設定形式、DBテーブルは増やしていない。判断のための入力と更新案の出力に相当するトークンは増える。従来形式の回答と保存済みの履歴は読み込める。`memory_updates` がない旧形式だけ従来の候補処理を使い、新形式の「変更なし」を語句の補完で覆さない。

- 全体 `ruff check .` と `ruff format --check .`：成功、277ファイルの書式を確認。最終pytestとRuffは個別実行であり、失敗した `test.bat` 自体を成功と表記しない。

### 実APIと隔離実アプリ

送信先は OpenAI公式Chat Completions、モデルは `gpt-6-luna`。通常データを使わず、既存人格と検査用の架空会話、そこから作った記憶だけを使用した。APIエラー後の自動再試行はない。

| 評価 | 結果 |
| --- | --- |
| 14ターンの実API | 趣味・休日の習慣・朝食の訂正・言い換えの重複防止・記憶拒否・第三者・創作・一時状態・記事引用・検索後の本人申告・新しい会話での参照・忘却・大切な経験を確認 |
| 最初の短答・隔離実アプリ | 返答はできたが、空のDBへ記憶が保存されなかった。元の更新案を残していなかったため、原因の全ては断定できない |
| 修正後の短答・隔離実アプリ | 「見る方と走る方、どちらが楽しい？」→「走る方だよ。」から「モトジムカーナは走る方が好き。」を承認済み記憶として保存 |
| モック・隔離実アプリ | PMX画面・通常会話・訂正後の一覧・新しい会話での参照を確認 |

短答では短い根拠引用を過剰に拒否しないよう修正し、発言全体を根拠にする指示も追加した。追加評価ではLLMの更新案、保存後のDB、実際の記憶管理画面を照合した。保存後の画面（開発PCだけの記録。配布物には含めません）。

初回の承認は16要求・各出力1536トークン・0.50米ドル。通信が遮断された1試行も枠に含め、その後14要求と最初の短答1要求で上限に達した。追加承認は2要求・各出力1536トークン・0.10米ドルで、修正後の確認に1要求だけ使用した。残る1要求は未使用。新しい有料評価を無断で開始しない。

要求の送信先・モデル・形式・入力サイズ・出力・件数を送信前に検査し、保守的な費用予約を行った。評価用DB、設定、QSettingsは通常環境から分離。通常の会話・保存記憶・写真・音声・PMXを外部に送っていない。

### 未確認と制約

- **実装済み・自動テスト済み・Codex環境の実API／隔離実アプリ確認済み**と、**利用者が感じる会話の自然さの受入待ち**を区別する。これだけでフェーズ10全体を受入完了にしない。
- 語句の一致を必須にしない方式だが、全ての言い回しで正確に保存・分類できる保証はない。曖昧な発言は保存しないことがある。引用等の取り違えを防ぐ補助判定にも限界がある。
- 参照・更新対象としてLLMへ渡す承認済み記憶は、関連候補を先にして最近のものを加え、最大40件・内容合計10,000文字。設定の経過日数を超えた記憶は参照から外すが削除しない。上限外の古い情報を意味だけで必ず検索できる仕組みではない。
- 自動承認がオフの内容は候補となり、承認までは本人の事実として会話に渡さない。候補の内容変更は管理画面で行える。
- 今回の実アプリ評価では音声出力・音声認識を無効にした。音声・口形の実再生を今回新たに確認したとは扱わない。関連する自動回帰検査と、以前の受入記録を分ける。
- 全体検査中に一度起きたQtの異常終了は、`ChatWindow._worker_finished` のワーカー参照を外す箇所で観測した。単独UI検査と最終全体検査では再現せず、原因は未特定。推測で終了処理を変更せず、`test-bat-final.log` と成功した `pytest-full-diagnostic.log` の両方を残す。

## 利用者が次に行う操作

目的は、決まった言い回しを使わずに、自分の話を覚えて会話に生かしてくれるかという自然さの確認。技術的な試験一式を繰り返す必要はない。

1. 雨衣のアプリを閉じ、いつもの `run.bat` をダブルクリックして開く。新しいAPI設定や移行操作は不要。
2. 右上の歯車 →「会話・音声」→「記憶を管理」で、「今後の会話で保存した記憶を使う」「候補を自動承認する」がオンなら自動保存になる。既存のチェック状態は変更しない。
3. 普段どおり、自分の本当の趣味や過ごし方を話す。例えば「休みの日は○○をして過ごしてるよ」の○○を実際の内容にする。「覚えて」を足す必要はない。前の質問への短い返答でも、対象が明確なら記憶される。毎回の保存通知は出さない。
4. 気になったときに「記憶を管理」を開く。趣旨が合っていて、訂正した古い内容が重複して使われず、後の会話にも自然につながれば成功。発言と異なる属性が保存されたり、明確に伝えた内容を継続して取りこぼす場合は未解消と判断する。
5. 読み上げを止めるときは「音声・動作を停止」。誤った記憶は一覧から選び「修正を保存」または「選んだ記憶を削除」で直せる。記憶自体を一時停止するなら「今後の会話で保存した記憶を使う」をオフにし、再開時にオンへ戻す。問題が残る場合は、直前の問い・本人の返答・保存された内容の違いを知らせる。
