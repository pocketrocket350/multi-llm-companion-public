# 設定・管理画面の整理（2026-09-22）

**履歴と現在の区別（2026-09-28）**：以下は初回整理の記録。表示幅の選択欄は境界ドラッグへ、表示範囲はモデル右上の人物アイコンへ移動済み。通常の設定に旧選択欄を戻さない。前髪の合成異常は[後続修正](preview-settings-fix_ja.md)で解消。現行操作と最新検証は[利用者向け手順](phase11-user-check_ja.md)・[仕上げ記録](phase11-finish_ja.md)を参照する。

## 修正前の採用範囲と判定条件

利用者の「全体的に改善」に基づき、通常設定の開発用操作を除き、記憶・表情・モーションの管理を使いやすくする。依存、公開バックエンドAPI、DB、YAML形式は変更しない。通常データと受入済み音声・アバターの動作設定を保護する。

- 設定の表示名から作用が分かり、全身／バストアップが選べる。表情・視線の単発テスト、VMD生成、VMDカメラ、動作のテスト用停止、状態表示の二重切替を通常画面へ出さない。
- 記憶は一覧の領域を優先し、最大化、Ctrl／Shiftによる複数選択、件数表示、選択した項目の一括承認・削除に対応する。複数選択で一件の編集文を他へ誤適用しない。
- 表情は一覧選択だけで表示を確認でき、確認操作では保存しない。編集と閲覧を分け、終了・割り込み時に確認中の表情を残さない。
- 管理画面の長文は折り返し、画面内に収まり、スクロールで全操作へ到達できる。800×600相当と高DPIで検証する。
- 既存の会話・検索・画像・記憶・音声割り込みの回帰を実行する。有料APIは呼ばない。全体 test.bat の失敗はそのまま記録する。

検証は隔離したDB・設定・QSettingsと試験データを用いる。バックアップは `local/diagnostics/settings-ux-20260922/before/`。前回のQtアクセス違反は未解消の記録であり、今回の成功証拠に過去のテスト件数を使わない。

## 実装した内容

- 設定を「会話・音声」「表示」「診断情報」に整理。表示幅は「ほぼ半分ずつ」「雨衣を広く」、表示範囲は「全身」「バストアップ」とした。「接続・人格・音声の設定」は実際の機能に合わせ「LLM接続・マイクの設定」へ改称。
- 表情・視線の単発テスト、待機VMD生成、VMDカメラ・照明、動作停止チェック、状態表示の二重切替はUIと専用ハンドラーを撤去。既存の内部描画・VMD互換APIと回帰テストは維持した。
- 記憶は左右の分割表示にし、検索、最大化、Ctrl／Shift複数選択、選択件数、一括承認・削除を実装。「保存しない」と「削除」の重複を解消。複数承認は各記憶の元の本文・分類を使用し、一件用の編集内容を流用しない。途中失敗では処理済み件数を出して一覧を再取得する。
- 表情は日本語の場面名を先に表示し、通常の表情を最初に選択。一覧選択だけで非保存プレビューし、「表情を編集」タブへ移す操作と分けた。空・解決不能なプリセットでは直前のプレビューを停止する。
- 表情・モーション管理の左側に現在の雨衣を表示。元のPMX描画を150msごとに共有し、モデルや描画器を追加作成しない。終了時にタイマーを停止する。高DPIでも論理サイズに合うようピクセル比を適用した。
- モーション一覧の高さを確保し、技術的な詳細は「選んだ動きの詳細」へまとめた。管理画面・接続設定・話しかけ設定はサイズ変更／最大化ができ、長い内容はスクロール可能。チェック変更が即時反映される画面ではそのことを明記した。
- 旧QSettingsの `companion_view=face` は雨衣を広く・バストアップとして読み込む。旧 `status_visible` の値は削除せず、診断タブでは概要を常に表示する。新しい設定キーは追加しない。

最初の対象検査ではQtアクセス違反と、変更前の偽ダイアログ／旧UIを想定したテスト不一致が出た。偽ダイアログは試験対象である割り込み確認を維持し、表示処理は別の実ダイアログ試験で検査した。視線の内部平滑化・割り込み検査も維持した。`target-01.log`〜`target-05.log`に失敗を残している。

画面終了後に親なしウィンドウが残ることを診断で観測し、テストの後始末をQtの遅延破棄→参照回収の順へ統一した。これにより対象121件、最終122件は成功したが、全体の異常までは解消していない。単独の参照回収だけでは失敗したため、その案は採用していない。Qtネイティブ異常の根本原因を確定したとは報告しない。

プレビュー共有の1回更新は12回の短い測定で100％表示の中央値8.13ms・最大8.67ms、150％で中央値11.00ms・最大12.95msだった（周期150ms）。これは固定した姿勢での描画取得だけの測定であり、長時間性能・音声同期の受入結果ではない。動画ではなく表情・登録動作の確認用表示で、通常描画より更新間隔が長い。

PMXの前髪・一部表情で水色の描画の乱れが見える。管理画面には元の描画がそのまま映る。描画品質の問題は今回未修正で、原本素材や受入済み表情・視線・動作設定を変更していない。新しい有料API、実音声の聴感検査、8時間待機は今回実行していない。

実画面・計測は `local/diagnostics/settings-ux-20260922/native-final/` と `native-150-final/`。後者は最後の説明文追加・空プリセット処理前の高DPI検証で、表示倍率処理は最終版と同じ。最終の説明文と空プリセット処理は100％実画面／最終対象テストで確認した。

## 利用者が次に行う操作

起動中のアプリを終了し、プロジェクトの `run.bat` から起動し直す。右上の「設定」から整理後の画面を開ける。普段の環境での選びやすさを確認する場合の操作、正常時の反応、終了・復帰方法は[画面の操作手順](phase11-user-check_ja.md#記憶と表情を管理する)に記載した。Codexが済ませた機能検査や、有料API送信を繰り返す必要はない。見切れ・選択の分かりにくさが残る場合は、画面名と操作を知らせればよい。
