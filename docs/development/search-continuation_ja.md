## 対象と実装

編集前の範囲・合否条件は `local/diagnostics/search-continuation-20260929/plan.md`、編集前コピーは同フォルダーの `before/`。9月28日までのUI修正を含む現在のファイルを控えた。

- 直前の雨衣の検索提案に対する「それでお願い」「お願い」「お願いします」「はい、お願いします」「うん」などを、既存の検索処理へつなぐ。「調べようか」「調べればいい」「調べる条件」など、未実施の検索内容を示した直前の返答に限る。雑談への同意、完了報告、否定、中止、例文の引用、返答のない中断済み依頼からは検索を開始しない。
- 検索へ送るのは、利用者が同意した直前の提案本文と短い検索指示。出典ラベルを取り除き、既存の400文字上限・秘密情報の検査・許可を通す。全履歴や保存記憶を検索APIへ追加送信しない。自由な日本語の全表現に対応する意味判定ではなく、対象不明の「お願い」だけでは検索しない。
- 元の画面末尾のような「調べる条件は『東京の…』」でも、括弧内に明示された東京を地域として認識する。位置情報や保存記憶から現在地を補う変更ではない。
- 検索中は白い吹き出しに「調べているよ。結果が分かったらここで伝えるね。」と表示する。検索・返答生成の完了後、追加入力なしで同じ吹き出しが出典付きの最終結果に変わる。途中表示はDB・記憶・音声へ入れない。結果がすぐ返る場合は途中表示が一瞬になる。
- 検索後の会話モデルへ、取得済みの結果を今の返答で説明し、不足する観測値・順位は不足として明示するよう指示する。通常会話のターンにはバックグラウンド検索を実行していない状態を伝え、架空の検索待ちを説明しないようにする。
- 過去の降水量には予報ページ用の指示を使わず、観測地点・単位・同期間をそろえた公開観測資料を求める。取得できない数値を予報・推測で埋めない。検索回数やタイムアウト上限を増やす変更、自動再検索は追加していない。
- 取消、停止、新しい入力、録音開始、許可無効化では、既存の世代管理で途中表示と遅着結果を破棄する。通信エラー時は途中表示を消し、エラーを出して普通の会話へ戻れる。

Python/PySide6、既存Provider・保存・音声・描画を利用する。依存・公開API・設定形式・QSettingsキー・DBスキーマの変更はない。描画・PMX/VMD・人格・通常の記憶・ボイスは変更していない。短い途中返事のためのLLM呼び出しや読み上げも追加していない。

### Qt停止の未解消記録

最初の関連3ファイル検査は、天気地域の聞き返しテスト中に停止した。30秒のfaulthandlerでGUIスレッドの `conversation_view.py:fit_width` → `QTextDocument.setTextWidth` を記録した。対象PID・作成日時・コマンド・親子関係を照合して当該pytestだけを終了し、`focused.log` と `focused-stopped.json` を保持した。全件成功には数えない。

原因診断として、Qtオブジェクトのスレッド外破棄の可能性を調べた。[Qt公式のQObjectスレッド規則](https://doc.qt.io/qt-6.8/threads-qobject.html)と既存の `tests/conftest.py` を照合したところ、既にGUI上で `deleteLater`・遅延破棄イベント・GCを実施していた。GC開始/終了スレッドを記録する診断では、199件が成功し、GCはGUIスレッドのみだった。今回の原因をワーカー上のGCと断定する根拠は得られなかった。製品の描画やテストcleanupを推測で変更せず、原因未特定として残す。診断後の成功によって、今回の停止や過去のAborted/access violationを解消扱いにしない。

停止したケースを含む関連7ケースの別診断では、吹き出し幅計算の入口/出口時刻、本文長、幅、GUIスレッドを `layout-events.log` に記録した。停止は再現せず7件成功。全体検査ではGUIがイベント処理内で待機し、Pythonフレームのない別スレッドがあり、過去の画像エラー復帰と同じテストで止まった。現在のログだけではQt内部の待ち先を特定できず、検索の新しい途中表示が原因とも、GCが原因とも断定しない。

## 利用者の次の操作

1. 起動中の雨衣アプリで処理中なら「検索・返答を取消」または「音声・動作を停止」を押す。終了待ち表示が消えたら×で閉じ、プロジェクトの `run.bat` をダブルクリックして再起動する。履歴・設定は残る。
2. 日常の検索で、雨衣が具体的な検索条件を提示したら、入力欄へ「それでお願い」と入力して右の三角矢印を押せる。今回の元の会話の最後が「調べる条件は…で合ってる」なら「お願い」でも同じ内容へ進む。確認のための有料送信を繰り返す必要はない。
3. 正常時は、白い吹き出しの短い返事と、入力欄上の「Web検索・返答のためOpenAIへ送信中」「検索・返答を取消」が出る。追加入力をせず待つと、吹き出しが結果・出典リンクに変わり、処理中表示が消える。読み上げを有効にしている場合の対象は最終結果だけ。
4. データ不足なら不足の説明、通信失敗ならエラーが出る。通信終了後に結果が届くと説明し続けることや、停止後に古い結果を表示・読み上げすることは不合格。「お願い」を連打せず、取消して表示と操作を知らせる。通信終了後は普通の会話を送って復帰できる。

Codexが確認した検索回数・保存・取消・画面一式の再試験は不要。利用者には普段の会話での返答の自然さと分かりやすさの判断を残す。実APIの出典内容や文章品質はモデル・取得資料に依存し、今回のMock成功とは区別する。
