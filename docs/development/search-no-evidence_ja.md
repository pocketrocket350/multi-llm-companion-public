**差分は実装済み。自動検査・隔離実PMXでの確認と、実API・実音声・利用者受入を以下のように区別する。フェーズ10/11全体の受入完了にはしない。**

## 今回の範囲と変更

編集前に `local/diagnostics/search-no-evidence-20260929/plan.md` へ対象・評価条件・合否を記録し、7ファイルを `before/` へ保存した。9月28日の画面修正、9月29日の検索継続修正を含んだ状態からの差分である。

- 検索が実行・完了したものの、本文と対応するURL出典を得られなかった場合を、認証拒否・タイムアウト・不正応答等とは区別する。未検証の外部本文は捨て、検索が完了して情報を確かめられなかったというアプリ側の状態だけを通常の会話モデルへ渡す。
- 保存済みの人格・口調で短い返答を生成し、既存の吹き出し・履歴・任意の読み上げへ接続する。「今回の検索では確かな資料を見つけられなかった」ことを伝え、資料自体が存在しないと断定しない。未確認の数値や順位、架空の待機・追加検索を約束しないよう指示する。
- 出典なし返答にURLや出典ラベルが混ざった場合は、自然な短い固定文へ置き換える。出典一覧・記憶候補・記憶更新は空にし、検索と会話生成の使用量は合算する。出典がない外部本文を事実・利用者の記憶として採用する変更ではない。
- 「それを調べて教えて下さい」には直前の雨衣が述べた対象を引き継ぐ。降水量・降水日数・気温の明示的な比較依頼も検索経路で扱う。引用・雑談・検索の否定は検索にしない。過去全履歴や保存記憶を検索APIへ渡さず、既存の400文字上限・秘密情報検査・許可を維持する。
- 停止・入力・録音開始・許可無効化後は、情報なしの返答も表示・保存・音声へ再適用しない。検索処理には世代管理に加えて既存の取消コールバックも渡し、検索中と返答生成中の両方で確認する。

検索1回に対し通常の会話生成1回という既存の経路を使用し、自動再検索や再試行を増やしていない。会話モデル自体が接続不能な場合まで発話を保証する実装ではなく、その場合は重大なエラーとして表示する。依存・公開API・設定キー・設定形式・DB形式・描画経路・PMX/VMD・ボイスの変更はない。

### Qt異常終了は未解消

通常の対象2ファイルの一括実行は、検索拒否/タイムアウトからの復帰を検査する `test_search_failure_shows_reason_then_returns_to_normal_chat` 中に `Fatal Python error: Aborted` で終了し、全件成功とは数えない。スタックはGUIイベント処理から `_worker_finished` → `_set_busy` → `busy_label.setText`。`focused.log` を保持し、PID・作成日時・起動コマンドを照合した当該pytest親子だけを終了した。`focused-stopped.json`。

原因診断ではworker終了signal、画面/スレッドの寿命、既存cleanupと過去記録を照合した。今回の停止はfixture破棄より前であり、スレッド外widget操作や破棄済みラベルが原因とは断定できない。上記のQt診断では再現しなかったため、原因は未特定。描画・cleanupを推測で変更したり、テストの削除・無効化・基準緩和で隠したりしていない。後続の成功によって今回と過去のQt停止/Aborted記録を消さない。

## 利用者の次の操作

目的は普段の会話として自然に伝わるかの判断であり、Codexの検索回数・保存・取消検査を再実行していただくものではない。

1. 処理中なら入力欄上の「検索・返答を取消」または「音声・動作を停止」を押す。終了待ちが消えたら右上の×で閉じ、プロジェクトの `run.bat` をダブルクリックして起動し直す。更新は起動中のアプリには反映されない。履歴・設定の削除は不要。
2. 次に普段の検索を頼む際は、右下の入力欄から送れる。元の条件を明記するなら「2026年9月1日から28日までの東京の降水量と降水日数を平年と比較して」。右の三角矢印、またはIME確定後のEnterで送る。直前の雨衣の返答に対象があれば「それを調べて教えて下さい」でも進める。失敗直後で雨衣の返答がない場合は、古い依頼を勝手に再利用せず、対象を含む文を使う。検査目的で有料送信を繰り返す必要はない。
3. 処理中の白い吹き出しと取消が出たら追加入力せず待つ。結果が得られれば出典付きの返答へ変わる。確かめられなければ「探してみたけれど、今回の検索では確かな資料を見つけられなかったよ」など、いつもの人格で伝える。実際の文面は固定ではない。普段の読み上げが有効なら、この返答も読み上げ対象となる。
4. 合格は、最終結果または見つからなかった説明が一度届き、処理中表示が消え、その後も普通に話せること。通信が終わったのに「届いていない」「調べるね」だけを繰り返す、情報なしが赤い表示だけになる、停止後に古い返答・音声が出る場合は不合格。
5. 止めたいときは同じ取消/停止を押す。終了待ちが消えた後に「お茶を飲もう」などを送れば普通の会話へ戻れる。認証拒否やタイムアウト等の通信障害はエラー表示を残す。問題時は追加入力を連打せず、押した操作・最後の表示・聞こえた内容だけ知らせていただければよい。APIキーや会話全文は不要。

指定Tanaka Sanでの実音声確認は利用可能になってからCodex側で再開する。現時点では読み上げ経路の検査と、実際に聞こえる声の確認を明確に分ける。60分会話・実時間8時間待機は新12のままで、今回開始していない。
