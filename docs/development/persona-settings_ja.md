# 設定画面から人格を編集する

2026-09-24。利用者の「雨衣の人格を設定している部分を設定の項目にしてください」に対応した。保存先はアプリ設定の既存 `persona_path`（通常は `local/persona.yaml`）を使う。

## 変更内容

「設定」→「会話・音声」に「人格を編集」を追加した。次の項目を日本語の入力欄で編集できる。

| 選択する項目 | 内容 |
| --- | --- |
| 話し方・性格 | 名前、一人称、口調、大切にすること、好み、キャラクターの設定 |
| 会話の方針 | 返答の長さ、質問頻度、話題や提案、反対意見、利用者の意思、親しさと距離感、説明、記憶の使い方 |
| 背景・表現 | 公式に確認した事実、このアプリでの解釈、推測で付け加えないこと、話し方の基準、避ける表現 |
| 会話例 | 利用者の言葉と返答例。追加・編集・選んだ行の削除 |
| 場面ごとの話し方 | 雑談、話を聞く、相談、冗談、説明、計画、距離や境界を伝える場面の方針 |
| 追加指示 | 既存の自由記述による人格・会話指示 |

現在の内容を読み込み、「保存」が成功した時点で次の通常会話・能動会話へ反映する。再起動後も維持する。編集画面を閉じる・キャンセルするだけでは変更しない。旧形式の人格は「名前・人格」の自由記述として扱い、形式を自動変換しない。

長い項目はスクロールでき、ウィンドウの拡大・最大化に対応する。保存・キャンセルは画面下部に常時表示する。名前の空欄や保存失敗は編集画面内で伝え、編集内容を残す。ファイルが外部で変更されていた場合は上書きせず、アプリの再起動を案内する。

編集中は能動会話のタイマーを一時停止し、読み上げ中なら既存の割り込み経路で止める。返答処理中・録音中・音声認識中は人格編集を開始しない。人格の保存で履歴・記憶・音声・アバターを作り直さない。LLMへ渡す回答形式の指定も保持する。

## 保存と承認範囲

既存の `PersonaConfig` とYAML形式を使用する。新規依存・環境変数・DB・QSettings項目は追加していない。人格の取得・保存用の小さなアプリ内部APIは、この設定項目追加依頼の実装範囲とした。

保存時は変更した上位項目の値だけを書き換え、未編集項目と先頭の出典コメントを保持する。値は同じYAML形式内の引用・フロー記法になる場合がある。人格のファイル全体を検証し、一時ファイルから置き換えることで、保存失敗時に既存ファイルを空にしない。編集対象の値の内部に置かれたコメントの維持までは保証しない。

今回の実装作業では通常の人格内容を変更していない。人格編集そのものではLLM要求を行わず、通常どおり次の会話時に設定中のLLMへ人格の内容を渡す。会話例は利用者の会話・長期記憶へ登録しない。

## 利用者が次に行う操作

今回は画面を利用可能にするための再起動だけが必要で、人格の変更内容は利用者が選べる。

1. 起動中のアプリを閉じ、プロジェクトの `run.bat` をダブルクリックする。読み上げ中なら、先に「音声・動作を停止」を押す。
2. 会話画面右上の「設定」→「会話・音声」→「人格を編集」を押す。
3. 上部の選択欄から編集したい項目を選ぶ。例えば口調なら「話し方・性格」、現在の長い人格指示なら「追加指示」を開く。リストは1行に1項目で入力する。
4. 反映する場合は右下の「保存」を押す。保存しない場合は「キャンセル」を押す。保存後は設定画面に戻るので、閉じて普段どおり話しかける。

正常時は保存した内容が再度開いた画面にも表示され、次の会話から利用される。次回起動時にも同じ設定が戻る。保存・再起動・キャンセルの一式検査はCodexで実施済みなので、確認のためだけに繰り返す必要はない。

保存エラーなら画面を閉じず、表示された理由を確認する。保存前の内容は維持される。「別の場所で変更」と出た場合は必要な下書きを手元に控えてキャンセルし、アプリを再起動してから開き直す。保存後に口調が好みと違う場合は同じ項目を編集して保存する。発話を止めたい場合は会話欄の「音声・動作を停止」を押す。保存されない・操作できない場合は項目名とエラー表示を知らせる。人格全文・通常会話・秘密情報の提出は不要。
