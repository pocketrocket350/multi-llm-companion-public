## 初回指摘への対応（保持）

| 指摘 | 対応と確認してほしい点 |
| --- | --- |
| 記憶の件数・関連度設定が最終入力へ反映されない | **一部採用**。`max_context_memories` を補完候補を含む全体へ適用。同じ話題の語句候補、話題補完、その他の語句候補、最近の承認済み記憶の順に選ぶ。`min_relevance_score` は語句検索の基準とし、意味判断用の補完には適用しない。この判断の妥当性、設定説明との整合、件数・文字数・期限・無効化の境界を確認してほしい。 |
| 停止待機期限後のWhisper再開で、旧workerが新しい録音を壊す | **修正**。旧workerが生存中は再開を拒否し、停止イベントとthread参照を保持する。停止後の認識結果を通知しない。Voskにも同じ保護を適用した。旧worker終了後の再開、設定変更による認識器の交換、停止と開始の競合を確認してほしい。 |
| 記憶保存失敗時に返答・感情・一部の記憶だけが残る | **修正**。返答・感情・記憶変更をSQLiteの入れ子トランザクションで一括確定。失敗時はDBと記憶通知用の状態を戻し、アバターと返答の公開は保存成功後に行う。利用者入力は保持する。MemoryServiceの直接呼び出しも対象。commit失敗、入れ子のロールバック、ロック順序、別threadからの利用も確認してほしい。 |
| 終了待機3秒より遅いDELETEがprocess終了で失われる | **修正**。最終終了は遅着HTTP操作・削除キュー・client closeの完了を待つ。通常停止の非同期動作と、明示した待機期限は維持する。予期しない削除・close例外は失敗として返す。実際のHTTPタイムアウト、遅着POST、例外経路、終了の上限について独立に確認してほしい。 |
| GitHub上で古いコミットを参照できる | **未解決・今回のコード修正対象外**。新しいコミットの公開で過去の参照やキャッシュが消えたとは扱わない。[公開履歴のメール保護](publication_privacy_ja.md)を参照。 |

語句の関連度を補完記憶にも厳密適用すると、「朝食はトースト」に対する「最近はご飯に変えたよ」のような訂正対象が入力から落ちる。
その既存機能を保持する判断であり、関連度設定を全候補の送信拒否として扱う修正ではない。
保存した記憶の利用全体を止めるには「今後の会話で保存した記憶を使う」をオフにする。
既定の候補件数は従来の固定40件から設定値の5件となる。全ての古い記憶を意味で検索できる保証はない。

## 公開テストの実行

秘密情報・個人設定を置いていない専用cloneで行う。
Python 3.12と、`pyproject.toml` の既存依存に加えpytestが必要。
既存の検証環境がなければ、専用仮想環境へインストールする。

Windows PowerShellの例：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c constraints-windows-py312.txt -e . "pytest>=8.3,<10.0"
$env:QT_QPA_PLATFORM = "offscreen"
.\.venv\Scripts\python.exe -m pytest -q -o "pythonpath=src ." tests
```

Linuxの専用レビュー環境の例：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e . 'pytest>=8.3,<10.0'
QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest -q -o 'pythonpath=src .' tests
```

子process検査にも修正版を使わせるため、上記のeditable installを使う。
Qt画面のない環境では `QT_QPA_PLATFORM=offscreen` を指定する。
LinuxではPortAudioなどOS依存により収集時点で失敗することがある。その場合、実行できた範囲と未実行を分ける。
有料API、実マイク、モデルのダウンロード、通常アプリの起動はこの再レビューに含めない。
補助スクリプトの `--live` は実行しない。テストから呼ぶ評価は既定の人工データのみ。

本体・テストを変更せず、検証不能な箇所をskipや偽モジュールで成功に置き換えない。
必要なら独立した再現コードを一時フォルダーに置き、前提と人工資源の範囲を記載する。
上記コマンドはローカル検証用の隔離ガードを自動設定しない。秘密情報のない使い捨て環境で実行する。

## Ruffの比較条件

今回のローカル検証はRuff 0.16.2を使用した。公開版の`pyproject.toml`には開発用Ruff設定を含めていない。
別バージョンや、既定の`--isolated`の結果をそのまま同一条件の不具合件数として扱わない。
次の内容をリポジトリ外の一時的な`ruff.toml`へ保存すると、対象範囲の設定を再現できる。

```toml
line-length = 100
target-version = "py312"

[lint]
select = ["E4", "E7", "E9", "F", "I", "UP", "B", "SIM"]

[format]
docstring-code-format = true
quote-style = "double"
```

その設定を`ruff check --config <一時ruff.toml> src scripts tests`と
`ruff format --check --config <一時ruff.toml> src scripts tests`へ渡す。
バージョン差に起因する指摘は分けて報告し、本体やテストを無関係に整形しない。
