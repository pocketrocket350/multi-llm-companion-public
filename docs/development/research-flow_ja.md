# 分野を限定しない調べ物の会話（2026-09-29）

利用者の「天気だけのピンポイントな修正ではなく、自然に調べ物を進め、できなければ理由を雨衣から告げてほしい」に対応する。[前の地域・期間継承の修正](search-context_ja.md)は履歴とし、その限定的な成功を今回の完成証明には使わない。統計比較の成功自体は受入条件ではない。

**実装済み。関連自動419件成功、隔離実PMXと下記範囲の実API確認済み。全体test.batはQtで停止して未合格。実音声・利用者実機受入は待ち。**

## 変更と理由

以前は、UIの特定語・地域判定で検索を開始し、LLMはそれとは独立して「調べるね」と返答していた。今回は既存の会話要求に二つの内部操作を渡す。通常の返事・必要な質問は `reply_to_user`、実検索は `request_web_search`。会話の意味からどちらかを選び、後者は同じターン中に検索・最終返答まで実行する。確認質問への回答、訂正、省略、話題変更は会話文脈で扱い、天気用の言い回しを追加しない。

- 現在のOpenAI公式・gpt-6-lunaでは、UIの旧正規表現判定を通さない。既存の `approve_web_search` 登録も消費する互換経路を保持した。Mock・互換接続用の旧経路は残す。GPT-6の他モデルには未検証のChat Completions関数呼出しを一律適用しない。
- 会話判断は普段の会話要求を置き換えるもので、通常会話に別の分類要求を追加しない。ただし操作定義の入力トークンは増える。検索するターンは判断・検索・最終返答の最大3要求。自動再試行・巡回・返信後のバックグラウンド検索は追加しない。
- 最初の応答は確定まで保持し、内部操作や検索の予告を途中読み上げしない。通常返事の初回表示・音声開始は応答完了後になる。画像・能動会話の経路は変更しない。
- 入力欄の上には実行中だけ「返事を考えています」「Webで調べています」「調べた内容をまとめています」と「返答を取消」を出す。新入力、録音開始、停止、許可オフは既存の世代管理へ接続し、遅着した発言・音声・表情を適用しない。
- 検索の認証拒否、通信失敗、時間切れ、上限、空本文、出典対応の不一致などは、確認できた理由を雨衣の発言として保存し、通常の任意読み上げへ渡す。例外本文・秘密・内部JSONをそのままセリフにしない。資料不足は既存の人格に沿った最終返答を使い、出典のない外部本文を渡さない。
- 公開メソッドの引数・戻り値、DB、保存JSON、設定形式・QSettingsキー、依存関係は変更しない。検索指示は一時的な内部値で、意味記憶へ保存しない。通常DB・人格・設定・素材は保護する。

関数呼出しの形式は[OpenAI公式ドキュメント](https://developers.openai.com/api/docs/guides/function-calling)、採用モデルのChat Completions条件は[GPT-6 Luna公式仕様](https://developers.openai.com/api/docs/models/gpt-6-luna)で確認した。既存の `reasoning_effort=none` を維持する。

## 利用者の操作と合否

1. 起動中の画面は、処理中なら入力欄上の取消／停止を押して終了を待ち、右上の×で閉じる。プロジェクトの `run.bat` をダブルクリックして更新後を開く。履歴・設定ファイルは削除しない。
2. 右上の歯車→「会話・音声」で「Web検索を許可」がオンなのを確認する。読み上げは普段の設定を使い、声を変更しない。
3. 普段知りたいことを入力欄へ書き、右の三角矢印で送る。例は「東京国立博物館が10月12日に開いているか、公式サイトで確認して」。天気専用の文や特定の語順は不要。聞き返された場合だけ不足する情報を答える。
4. 実際に検索すると「Webで調べています」と取消が出る。追加で「お願い」を送らず待つ。白い吹き出しに結果と出典、または確かめられなかった理由が返る。読み上げが利用できる場合は発言本文だけを話し、URL・出典番号・時刻は読まない。
5. 「調べるね」だけで処理が終わらず、追加入力なしに結果か理由が返れば目的に合う。必要な質問が自然か、返答が読みやすいかを日常会話の中で判断する。Codexの検査一式を再実行する必要はない。
6. 止めるときは入力欄上の「返答を取消」または「音声・動作を停止」。取消の終了待ちが消えたら「別の話をしよう」と送って会話を続ける。新しい入力を書き始めたり録音を始めたりしても古い検索は取り消す。
7. 予告だけで終わる、理由が赤い表示だけになる、停止後に古い発言・音声が戻る場合は追加送信を止め、入力した短い文と画面の状態を知らせる。会話DBやAPIキーを送る必要はない。

## 最終の全体検査

`test.bat`を一度実行し、**1,684件収集、1,630件のPASSED行を記録した後、Qtの本文幅計算で停止した。全体未合格**。`test-bat.log`、`test-bat-result.json`。245.06秒でタイムアウト判定。通常権限での終了はアクセス拒否だったため、コマンド行・親子関係を照合した今回の検査PIDだけを権限付きで終了し、消滅を確認した。今回の現象はタイムアウトで、過去のAbortedと同一原因とは断定しない。

停止したのは `test_weather_clarification_respects_topic_changes_and_permission[other_topic]` の「紅茶を飲もう」への2回目の返答。MockProviderで検索は禁止されており、新しい実検索や有料APIを待っていたわけではない。`_message_succeeded → _render_messages → ConversationView._fit_messages → _MessageBubble.fit_width → QTextDocument.setTextWidth` が停止スタック。

原因診断としてGUIスレッド・Qtオブジェクト有効性・幅計算の再入・GC・Qtメッセージを記録した。`diagnose_qt.py`／`qt-events.log`／`qt-diagnostic.log`。UI等137件の診断実行は成功し、1,596回の幅計算はすべてGUIスレッド・有効なオブジェクト・再入なしだった。その実行で再現しなかっただけで、全体停止の解消証明にはしない。

全体ダンプのVoiSona監視スレッド14本は、先行する音声テストの `monitor_interval=999` とパラメーター展開数に一致する。`stop()` は世代を無効化するが、sleep中のスレッドは直ちには終わらない。残留経路は特定したが、Qt停止との因果は未立証。診断時のworker側GCも記録したが、Qtオブジェクトの誤破棄の証拠はない。描画や音声を推測で書き換えず、**根本原因は未特定・未解消**として残す。テストの削除・無効化・基準緩和・全件の反復実行は行っていない。
