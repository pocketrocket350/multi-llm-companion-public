# 自然な本人申告の記憶漏れ修正（2026-09-25）

## 対象と原因

利用者は天気の改善を確認した一方、「うん。モトジムカーナが趣味です」が記憶一覧へ入らないと報告した。前の修正は「私は○○が好き／大好き／苦手」という文型だけを補完し、相づち、主語の省略、趣味の言い方を拾えていなかった。

検索・画像の結果から利用者の恒久的な事実を作らないため、外部結果がある会話ではモデルの記憶候補を抑止している。その後の本人申告を補完するローカル処理の不足であり、利用者に特別な保存命令を要求する仕様ではない。

今回の対象は、この本人の好み・趣味の取りこぼしと保存・再利用の回帰確認。天気検索、画面配置、人格、音声、PMX・表情・視線・モーションは変更しない。依存関係、公開API、設定・保存形式、DBスキーマの変更なし。通常のDBへ試験データを入れず、過去の会話の一括再解析も行わない。

## 実装したこと

- 「うん。」「はい、」等の相づちに続く最初の本人申告を扱う。
- 「○○が趣味です」「趣味は○○」「私の趣味は○○」「○○を趣味にしてます」、主語を省いた「紅茶が好きなんだ」等を候補にする。
- モデルの候補が空、または不適格でも本人が明言した好み・趣味を補完する。呼び名・予定の既存の候補処理は維持する。
- 趣味の語順や「ユーザー／利用者」の違いで同じ記憶を増やさない。「訂正。私の趣味は読書ではなく登山です」のような訂正は旧値を置き換える。
- 自動承認オンなら承認済み、オフなら確認待ち。無効化、取消、忘却、秘密情報・引用・仮定・否定・保存拒否を尊重する。外部結果自体を記憶しない。

これは日本語全般を完全に理解する抽出器ではない。ローカルで補完するのは明確な好み・趣味等の宣言で、複雑な伝聞、代名詞だけの返答、自由な説明すべてを新たに解析する機能ではない。通常のモデル候補の経路は既存どおり。検索・画像を含む会話の一般的なモデル候補抑止も維持する。

## 普段の操作

1. 雨衣のアプリを閉じ、いつもの `run.bat` で再起動する。使っている記憶設定は維持される。
2. 次の普通の会話で「うん。モトジムカーナが趣味です」など、伝えたい趣味を話す。特別な「覚えて」の命令や専用フォームは不要。
3. 歯車の設定から「記憶を管理」を開くと、自動承認オンでは「ユーザーの趣味はモトジムカーナ」が承認済みで出る。重複・再起動・新しい会話への受け渡しはCodex側で検査済みなので、同じ手順を重ねて試す必要はない。
4. 保存したくないときは「覚えないで」、保存後に消すときは記憶一覧でその項目を選び「選択した1件を削除」を使える。読み上げを途中で止めるときは「音声・動作を停止」。
5. まだ保存されない／別の意味で保存される場合は、そのときの入力文と記憶一覧が手掛かりになる。以前保存されなかった内容は、今回の修正だけで通常DBへ遡って追記されない。
