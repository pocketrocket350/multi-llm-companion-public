# 初心者向けガイド

## このガイドについて

このガイドは、Windows 11でPythonアプリを初めて動かす人向けです。最初は外部APIを使わないMockで確認します。APIキーを用意する必要はありません。

まだフォルダーを取得していない場合は、先に [配布版のダウンロードと展開](release_ja.md#ダウンロードして起動する) を行ってください。ZIPの中から直接実行せず、新しい書き込み可能な場所へ「すべて展開」します。

## 最初に覚える言葉

- Python: このアプリを動かすためのプログラミング言語
- PySide6: Windowsの画面を作るための部品
- LLM: 入力された文章から回答を作るAI
- Provider: LLMサービスごとの違いをまとめる接続部品
- Mock: 外部へ接続せず、決まった方法で返答する試験用Provider
- APIキー: 外部サービスを使う人を確認する秘密の文字列
- YAML: 人が読みやすい設定ファイル
- SQLite: 会話履歴を1つのファイルへ保存する小型データベース
- 仮想環境: このアプリ専用にPythonパッケージを入れる場所

## 1. Python 3.12を準備する

1. Python 3.12を公式の配布元からインストールします。
2. インストーラーで「Add python.exe to PATH」を有効にします。
3. インストール後、いったん開いているフォルダやコマンド画面を閉じます。

別のPython版が入っている場合でも、このプロジェクトではPython 3.12を使ってください。

## 2. セットアップする

1. multi-llm-companionのフォルダを開きます。
2. setup_windows.bat をダブルクリックします。
3. 黒または青いコマンド画面が開くので、終了メッセージまで待ちます。
4. エラーがなければ、.venvとlocalフォルダが作られます。

.venvは、このアプリ専用のPython環境です。中のファイルを手作業で編集する必要はありません。

localには、見本からコピーされた利用者用の設定を置きます。configのexampleファイルは公開用の見本なので、普段の変更はlocal側で行います。既存のlocal設定を上書きする操作は避けてください。

主な設定ファイルは次の6つです。

- local/app.yaml: active_provider、providers_config_path、persona_path、database_path、audio_config_path、memory_config_path、avatar_config_path
- local/providers.yaml: providersと、その下の各Provider設定
- local/persona.yaml: オリジナル人格のcharacter、behavior_policy、dialogue_modesなど。見本と同じv2形式で編集します
- local/audio.yaml: マイク音声認識とVoiSona Talk音声出力
- local/memory.yaml: 長期記憶を会話へ使うかどうか
- local/avatar.yaml: 2Dアバターの見た目と、3D連携・PMX簡易プレビュー

## 3. Mockで起動する

候補にPMX・VMD・画像・音声素材はありません。必要な場合は利用者自身が正規配布元から取得し、利用と再配布の条件を別々に確認して `local` へ導入します。[アバター](avatar_ja.md) と [VMD登録](vmd_catalog_ja.md) を参照してください。Mockの起動には外部素材は不要です。

1. local/app.yamlのactive_providerがmockになっていることを確認します。
2. run.bat をダブルクリックします。
3. チャット画面が開くまで待ちます。
4. 使用中プロバイダー名、使用中モデル名、接続状態を確認します。

見本設定から始めた直後は、APIキーなしで試せるMockを使う想定です。実際の初期値は、コピーされた設定ファイルを確認してください。

## 4. 文章を送る

会話欄の下に入力欄と送信アイコンがあります。履歴一覧は左上の時計アイコン「履歴」、設定は右上の歯車「設定」から開きます。「設定」→「診断情報」でProvider、モデル、接続状態、トークン使用量を確認できます。トークン使用量はAPIが返した件数で、料金そのものではありません。

1. 右側の文章入力欄をクリックします。
2. 例として「こんにちは」と入力します。
3. Enterを押して送信します。複数行にしたいときはShift+Enterで改行します。
4. 自分の文章が会話表示欄へ出ることを確認します。
5. 処理中表示が消え、Mockの回答が出ることを確認します。

処理中は二回目の送信ができません。回答またはエラーが表示されるまで待ちます。「新しい会話」を押すと、空の会話が左側の履歴へ追加・選択されます。

## 5. 会話を分ける・削除する

別の話題を新しいまとまりにしたいときは、「新しい会話」を押します。以前の会話を消す必要はありません。

履歴削除は元に戻せません。必要な内容がある場合は、削除前に利用者自身で安全な場所へ控えてください。dataフォルダ内のデータベースを、アプリ実行中に直接編集しないでください。

## 6. テストする

1. アプリを閉じます。
2. test.bat をダブルクリックします。
3. pytestの失敗がないことを確認します。
4. ruffの失敗がないことを確認します。

pytestは機能を自動確認し、ruffはコードの単純な間違いや書式を確認します。どちらかが失敗した場合は、成功したとは判断しません。表示を最初から最後まで控え、原因を調べます。

## 外部LLMを使う前の注意

外部LLMを使うと、入力した文章や、必要に応じて過去の会話・人格設定がAPIサービスへ送られます。個人情報、パスワード、会社や学校の秘密、公開してはいけない文章を入力しないでください。

サービスごとに料金、利用上限、利用規約、データの扱いが異なります。公式資料と管理画面を確認してから利用してください。

APIキーはYAML、Pythonコード、ログ、メモとしてリポジトリ内へ保存しません。Windowsの環境変数からだけ渡します。詳しい方法は providers_ja.md を参照してください。

## 設定を変更するとき

1. アプリを閉じます。
2. 変更するlocal側のファイルを、別名でバックアップします。
3. config内のexampleファイルと見比べます。
4. インデント（行の先頭の空白）を崩さず、必要な値だけ変えます。
5. APIキー値を書いていないことを確認します。
6. run.bat で起動し、画面の状態表示を確認します。

YAMLでは、行頭の空白が構造を表します。Tabキーではなく、見本と同じ数の半角スペースを使ってください。

## よくあるエラー

### Pythonが見つからない

Python 3.12がインストール済みか、「Add python.exe to PATH」を有効にしたか確認します。インストール後は、新しいフォルダ画面またはコマンド画面からやり直します。

### .venvがない

setup_windows.bat が途中で失敗した可能性があります。表示されたエラーを確認し、ネット接続やPythonの版を直してから再実行します。.venvを手作業で別の場所からコピーしないでください。

### 設定ファイルがない

setup_windows.bat を実行し直します。それでも作られない場合は、configのexampleファイルを元にlocalへコピーする必要があります。ファイル名はセットアップ画面と見本構成を確認してください。

### YAMLを読めない

行頭の空白、コロン、引用符を確認します。直前の編集を戻し、見本と少しずつ比較します。APIキーをエラー報告へ含めないでください。

### 認証エラー

環境変数名が設定例と一致しているか、APIキーが失効していないか、対象サービスのキーか確認します。キー値を画面写真や質問文へ貼らないでください。

### 接続タイムアウト

タイムアウトとは、決められた時間内に返答がなかった状態です。ネット接続、base URL、サービスの稼働状況を確認します。設定のタイムアウト値を極端に大きくする前に原因を確認してください。

### 文字化けする

Windowsやターミナルの文字コード設定により、日本語が崩れる場合があります。ファイルはUTF-8で保存し、バッチファイルを通常のWindows環境から実行してください。文字化けしていても、APIキーらしき文字列をそのまま共有しないでください。

## 困ったときに控える情報

次の情報があると原因を調べやすくなります。

- どのバッチファイルを実行したか
- どの操作で止まったか
- Pythonのバージョン
- 使用中のProvider名
- エラー全文
- test.bat の結果

APIキー、環境変数の値、個人情報、非公開の会話本文は隠してください。推測で「成功した」と判断せず、画面表示とテスト結果で確認します。

## 第2段階の終了位置

文字チャットに加えて、必要な利用者は `audio_ja.md` の手順でマイク音声認識とVoiSona Talk音声出力を確認できます。音声を設定していない場合でも文字チャットが動作すれば、後から安全に設定できます。

## 音声入力を改善する

「設定」でWhisperまたはVoskと、使用するマイクを選択できます。Whisperは高精度、Voskは軽量です。Whisperを初めて使う前に `download_whisper_model.bat` を実行してください。

マイク入力中は画面上部の音量と認識途中の文章を確認できます。話し終わった後の無音を検出すると自動停止します。音量メーターが動かない場合は、設定画面で別のマイクを選びます。

## 7. 長期記憶を使う

長期記憶は既定で候補を自動承認して保存します。「設定」→「会話・音声」→「記憶を管理」で確認・修正・削除できます。確認してから使いたい場合は「候補を自動承認する」を外します。その場合だけ、確認待ちの候補は「承認して保存」を押すまで会話の参考になりません。実装や人格・記憶の指示は変更せず、詳しい操作は [記憶の説明](memory_ja.md) を参照してください。

APIキー、パスワード、会社や学校の秘密、他人の個人情報は保存しないでください。「覚えないで」または「記憶しない」と書いた発言からは候補を作りません。詳しくは `memory_ja.md` を参照してください。

## 8. 感情状態を見る

画面上部の「感情」には、アシスタントの現在の感情と強さが表示されます。通常、喜び、悲しみ、怒り、照れ、驚きのように表示されます。

感情は会話ごとに保存されます。現在の状態は「設定」→「診断情報」で確認します。アバターの口形は取得したWAVの実再生位置を基準に進み、「音声・動作を停止」で止められます。利用許諾を確認したPMXは `local/models/mmd` へ置いて設定します。表示や管理は [最新の画面手順](development/phase11-user-check_ja.md)、詳しい仕様は `emotion_ja.md` と `avatar_ja.md` を参照してください。

## バックアップ・復旧とv1.0候補

設定だけでなく、会話と記憶が入ったDB、Windowsに保存される画面の好みも必要に応じて保存します。アプリを終了してから [バックアップと復旧](backup_and_recovery_ja.md) の番号順に進めてください。素材や秘密を含む個人用バックアップは配布物に入れません。

採用構成、同梱しない素材、既知の制限、クリーンWindowsで残る確認は [v1.0候補の導入](v1_candidate_ja.md) を参照してください。Mock最小構成は設定上の最小構成であり、セットアップは既存の全依存関係を導入します。
