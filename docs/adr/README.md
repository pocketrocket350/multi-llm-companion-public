# Architecture Decision Records

このフォルダーは、複数案を比較したうえで採用した、変更コストの大きい設計判断を残す場所です。障害記録、調査メモ、一般的な開発知識は`docs/knowledge/`へ置きます。

## ADRにする条件

次をすべて満たす判断だけをADRにします。

1. 現実的な複数案を比較した。
2. 採用理由と不採用理由が明確である。
3. 現行コード、設定、公開APIと矛盾しない。
4. 自動テストまたは実モデル確認の証拠がある。
5. 将来変更した場合の互換性、データ、性能、権利、安全性への影響が大きい。

提案段階の案は`docs/proposals/`、検証済みの再利用知識は`docs/knowledge/`に残します。ADRは知識の自動昇格先ではなく、親エージェントが採否を決めます。セキュリティ、データ保存、公開API、後方互換性に関わる判断は、利用者の承認とSol Advisorの読み取り専用レビューを得てから`accepted`にします。

## 状態

- `proposed`: 比較と確認の途中
- `accepted`: 採用済みで現行実装を拘束する
- `rejected`: 比較したが採用しなかった
- `superseded`: 新しいADRへ置き換え済み

廃止したADRも削除せず、`superseded_by`と理由を残します。

## ファイル名

`ADR-0001-short-title.md`のように、連番と短い英数字の題名を使います。

```markdown
---

status: proposed
date: YYYY-MM-DD
scope:

supersedes: null
superseded_by: null
---

## 採用理由

## 再検討する条件
```

APIキー、認証情報、利用者会話、外部LLMの生回答、第三者素材、公開できない実機ログは含めません。非公開証拠は内容をコピーせず、確認した種類と結果だけを書きます。
