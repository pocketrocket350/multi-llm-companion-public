# 採用構成の導入と停止・復帰

これは新しく展開した候補で、Mockから雨衣MMD・VoiSona Talk・採用済みの会話機能へ進む手順です。現在使っているフォルダーへ重ねて適用しません。既存利用者は通常設定を保ち、この手順を受入試験として繰り返す必要はありません。

初期状態はMock、音声・3D・能動会話は無効です。gpt-6-lunaとHTTP/2、人格・記憶の処理は維持します。個人の人格・会話・記憶は同梱しません。個人環境を移す場合は [個人用バックアップと復元](backup_and_recovery_ja.md) を使います。

## 1. 作業前の状態

1. [配布候補の導入](release_ja.md)に従い、新しいフォルダーで `setup_windows.bat` を完了します。
2. `run.bat` でMockの文字会話ができることを確認して閉じます。
3. エクスプローラーの **表示 → 表示 → ファイル名拡張子** をオンにします。YAMLを編集するときは、右クリックからメモ帳で開き、UTF-8で保存します。`.yaml.txt` にしません。
4. `local/app.yaml` を同じ場所へコピーし、`app.before-reference.yaml` と名前を変えます。同名のバックアップがあれば別の名前にし、上書きしません。

## 2. 採用した表情とPMXを導入する

追加見本 `config/avatar.reference.example.yaml` は、現PCで採用した **38プリセット、6感情の割り当て、6感情別の候補、103の表情モーフ対応** を保持します。口形・視線・姿勢・動作抑制・待機VMDの技術設定も引き継ぎます。初期Mock用の `avatar.example.yaml` とは用途が異なります。

対象は採用記録の `雨衣_2025_0516.pmx` です。別版・別モデルへの互換性を保証しません。この見本は本プロジェクトで調整した数値・接続名であり、PMXの形状・テクスチャ・公式人格・音声は含みません。モデルの利用条件は別に確認します。

1. [権利と入手先](rights_and_credits_ja.md)を確認し、正規に取得したPMXと付属テクスチャを、フォルダー構造を保って新しい候補の `local/models/mmd/` 内へ置きます。
2. `config/avatar.reference.example.yaml` を **コピー** し、`local` に貼り付けて `avatar.reference.yaml` に名前を変えます。既に同名ファイルがあれば止まり、上書きしません。元の `local/avatar.yaml` は残します。
3. コピーした `local/avatar.reference.yaml` を開き、`three_d` 内の `model_path: ''` を実際のPMXの相対パスへ変更します。例：`model_path: local/models/mmd/導入したフォルダー/雨衣_2025_0516.pmx`。`provider: pmx_preview` はそのままです。
4. 同じ `three_d` 直下の `enabled: false` を `enabled: true` にします。下の `thin_cloth_contact.enabled` など、別の項目は変えません。空白の数を保って保存します。
5. `local/app.yaml` の `avatar_config_path` を `local/avatar.reference.yaml` に変更します。項目がなければ、末尾の行頭へ `avatar_config_path: local/avatar.reference.yaml` を1行追加します。既存項目を重複させません。`config` の見本を直接指定しません。
6. `run.bat` で起動します。PMXが表示され、**設定 → 診断情報** の3D連携・表情・VMDに読み込みエラーがなければ設定読込みは成功です。待機は `sample_otokam_048`、モーションライブラリは有効です。同梱26件の有効19件・無効7件を維持します。
7. 表情の確認には **設定 → 表示 → 表情を管理** を使います。保存済みプリセットを選ぶと自動でプレビューされます。顔へ反映されることを確認し、**プレビューを終了**、**閉じる** の順に押します。「対応するモーフが不足」と出る場合は成功とせず、モデルの版と配置を確認します。自動検査だけで新規環境の見た目を実機受入済みとはしません。

モデルが出ない、対応する表情が見つからない、大きく崩れる場合は、別の名前や数値を推測して連続変更せず終了します。`local/app.yaml` の `avatar_config_path` を元の `local/avatar.yaml` に戻して起動すると2Dへ復帰できます。必要ならアプリ終了後に `app.before-reference.yaml` を元に戻します。PMX・VMDを削除する必要はありません。

## 3. 採用LLM・ボイス・マイクを設定する

1. [LLM設定](providers_ja.md)に従い、Windows環境変数へ接続情報を設定します。採用モデルは `gpt-6-luna` です。HTTP/2は既存実装が使用します。
2. [音声ガイドの手順5～7](audio_ja.md#5-voisona-talkを準備する)でVoiSona Talkと雨衣のボイスを正規導入し、利用できる `voice_name` を確認して `VOISONA_TALK_VOICE_NAME` に設定します。名前を推測せず、表示された値を使います。空欄や不一致なら合成を止め、別ボイスは使いません。
3. `local/audio.yaml` の `voice_output.enabled` を `true` にします。必要なマイクは音声ガイドでモデルを導入し、**設定 → 会話・音声 → LLM接続・マイクの設定** で認識方式と入力機器を選び、**保存** します。
4. アプリを再起動し、**設定 → 診断情報** でプロバイダー・モデル・音声出力・音声認識の状態を確認します。「設定済み」は設定値がある状態で、まだ実音声の成功証拠ではありません。
5. 料金・利用上限を確認したうえで、初めての導入先で通常会話を使い、選んだボイスから聞こえることを確認します。マイクは入力欄右の **マイク** で開始し、認識文を確認して送信します。既に受入済みの現PCで同じ試験を再度行う要求ではありません。

別の声、無音、認識誤りがあれば **音声・動作を停止** または **録音停止** を押し、必要ならアプリを閉じます。音声ガイドのエラー案内で設定を直すまでは、音声を無効にしてMockへ戻します。

## 4. 能動的な話しかけを使う

1. **設定 → 会話・音声 → 能動的な話しかけ** を開きます。
2. **能動的な話しかけを有効にする** をオンにします。読み上げる場合だけ **能動発話を読み上げる（現在の音声設定を使用）** もオンにします。
3. 待機時間・最短間隔・静かな時間帯を確認して **保存** します。現在のLLMへ人格と開いている会話の文脈を送るため、実APIでは料金が発生し得ます。
4. **設定 → 診断情報** の「能動会話」が「有効（音声あり）」または「有効（文字のみ）」なら設定成功です。すぐに発話しないことは異常ではありません。

停止は同じ画面で有効チェックを外して **保存** します。実行中の音声は **音声・動作を停止** で止めます。設定を保存できない場合は終了し、勝手に待機時間を短くして繰り返し試しません。

## 5. 検索・画像共有の許可と取消

許可は **設定 → 会話・音声** で確認し、チェック変更はすぐ保存されます。送信済み通信や発生済み料金は、取消操作でも元に戻りません。

- **検索**：**Web検索を許可** をオンにして、調べたい内容を書き **送信** します。検索中の表示と **検索・返答を取消** が現れ、完了後に出典リンクが残れば成功です。エラー時は連続再送せず、取消または終了します。今後使わない場合は許可をオフにします。
- **画像**：**画像の送信を許可** をオンにして、入力欄下の **画像を添付** からPNG/JPEG/WebPを1枚選びます。プレビューだけでは送信しません。質問を書き **送信** すると外部へ送ります。履歴に縮小画像と回答が残れば成功です。送信前は **画像を外す**、送信中は **画像・返答を取消** で止めます。

画像の後続質問では既出の説明文を引き継ぎます。新しい細部には再添付が必要です。許可がない、または接続先が非対応なら実行せず、表示された案内を確認します。操作番号・エラー・診断状態を控える場合は、キーや非公開の会話を含めません。

## 6. 保存・復帰の確認範囲

終了後に再起動し、左上の三本バー **履歴** で会話を再開できます。設定・履歴・記憶・画面の好みの移行は [バックアップと復旧](backup_and_recovery_ja.md) に従います。

現在の候補は非公開です。クリーンWindows未確認、速度目標未達、Phase 12既知事項は [候補の制限](v1_candidate_ja.md#既知の制限と了承済み事項) として保持します。今回の手順追加は、了承済みの受入の取消や、新しい有料試験・長時間試験の依頼ではありません。
