# AIの接続先を設定する

初期状態の **Mock** は外部通信をせず、固定応答を返します。AIと会話するには、利用するAPIサービスの契約とAPIキーが必要です。会話・人格設定・関連する記憶などが送信されるため、料金とデータの扱いを確認してください。

## 画面から入力する

**設定 → 環境設定 → LLM・VoiSona Talkの接続設定** に、使用するLLMの選択とAPIキー・接続先URL・モデル名をまとめています。**環境変数で設定** のチェックを外すと画面から入力でき、Windowsで暗号化して保存します。接続先の選択も入力値も再起動後に反映します。詳しい操作と復旧方法は [環境設定のガイド](environment_settings_ja.md) を参照してください。

一覧にないOpenAI互換APIを登録するには、同じ画面で **接続先を追加 → 名前を入力して確定 → URL・APIキー・モデル名を入力 → 保存 → 終了 → 起動** と操作します。既存の接続先は一覧から選んで編集でき、呼び名は **名前を変更** で変えられます。YAMLの手動編集は不要です。API形式が互換であることは提供元の資料で確認してください。

削除する場合は **対象を選択 → 接続先を削除 → 名前と切替先を確認 → 削除を予約 → 保存 → 終了 → 起動** です。保存すると対応する画面入力のAPIキーも保護ストアから削除します。確認画面はキャンセルが初期選択で、編集画面全体のキャンセルでも未保存の削除を取り消せます。復旧用のmockと最後の1件は削除できません。環境変数・`.env`は変更せず、提供元のAPIキーは失効させません。詳しい条件は [削除の手順](environment_settings_ja.md#接続先と保存済みapiキーを削除する) を参照してください。

**接続テスト** で、保存前のURL・モデル名・APIキーを確認できます。固定の短い文章を1回送り、料金が発生する場合があります。結果は日本語で表示し、設定は保存しません。環境変数方式では環境変数だけを使います。会話履歴や音声情報は送らず、通常の会話・音声の全機能の確認は含みません。[接続テストの手順](environment_settings_ja.md#保存前に接続を確認する) を参照してください。

## 従来の環境変数でOpenAIを使う

初期状態の **環境変数で設定** をオンのまま使う場合の手順です。

1. アプリを終了します。Windowsのスタートで「環境変数」と検索し、**環境変数を編集** を開きます。
2. 利用者環境変数の **新規**（既存項目は **編集**）で、次を登録します。

| 変数名 | 値 |
| --- | --- |
| `OPENAI_API_KEY` | 自分のAPIキー |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` |
| `OPENAI_MODEL` | 基準構成は `gpt-6-luna` |

3. **OK** で閉じ、アプリを起動するフォルダーやターミナルも開き直します。
4. アプリの **設定 → 環境設定 → LLM・VoiSona Talkの接続設定** で、**環境変数で設定** をオンのまま **使用するLLM接続先** を `openai` にして保存し、アプリを終了します。
5. **起動** ショートカットで起動し、**設定 → 診断情報** のプロバイダーとモデルを確認してから文章を送ります。

利用できるモデルはAPIアカウントの権限によります。キーをYAML・コード・ログへ書かず、画面写真にも含めないでください。Windowsの環境変数は `.env` より優先されます。変更が反映されない場合はWindowsへサインインし直します。

## その他の接続先

`local/providers.yaml` にOpenAI互換API用の見本があります。

| `active_provider` | 環境変数 |
| --- | --- |
| `qwen` | `QWEN_API_KEY`・`QWEN_BASE_URL`・`QWEN_MODEL` |
| `deepseek` | `DEEPSEEK_API_KEY`・`DEEPSEEK_BASE_URL`・`DEEPSEEK_MODEL` |
| `mock` | 不要 |

接続URLとモデル名は提供元の資料で確認します。接続先は **設定 → 環境設定**、認識方式・マイクは **設定 → 音声 → マイクの設定** で選べます。

### OpenAI・Qwen・DeepSeekの3社に限られるのか

この3名は初期の設定例です。3社とも同じ `OpenAICompatibleProvider` にURL・APIキー・モデル名を渡し、OpenAI互換のChat Completions形式で接続します。接続先名を3社に限定するコードはなく、画面の **接続先を追加** から増やせます。既存の `local/providers.yaml` の定義もそのまま一覧へ表示されます。

別サービスも同じ認証・要求・応答・ストリーミング形式を満たす必要があります。非互換APIには専用の接続処理が必要です。Web検索・画像共有は現在のOpenAI公式接続向けの処理であり、任意の互換APIで自動的に利用可能になるものではありません。

当初なぜこの3社を選んだかという個別の理由は、確認できた設計資料には明記されていません。設計資料で確認できるのは「まず共通の互換接続処理を使い、固有機能が必要なら専用処理を追加する」という方針です。

Web検索・画像共有はOpenAI公式API接続で利用します。設定中のモデルが非対応の場合はエラーになり、別モデルへ自動で切り替えません。操作は [会話のガイド](conversation_ja.md) を参照してください。

## 詳細設定

`local/providers.yaml` の各接続先では `temperature`（回答のばらつき）、`max_output_tokens`（出力上限）、`timeout`（待ち時間・秒）を調整できます。接続先・キー・モデルには値ではなく、それぞれ `base_url_env`・`api_key_env`・`model_env` に環境変数名を書きます。見本は [providers.example.yaml](../config/providers.example.yaml) です。

OpenAI公式APIのGPT-5/6系では `temperature` を送信しないため、この値を変えても反映されません。送信時のAPI差異やHTTP/2接続の再利用はアプリが処理します。通常は送信形式を変更する必要はありません。

## 接続できないとき

モデル名・環境変数名・URL、キーの有効期限、サービスの利用上限を確認します。キーの値を表示して調べる必要はありません。外部通信なしの動作確認へ戻すには、接続設定画面で **使用するLLM接続先（再起動後）→ mock → 保存 → 終了 → 起動** と操作します。詳細は [復旧手順](backup_and_recovery_ja.md#起動や接続で困ったとき) を参照してください。
