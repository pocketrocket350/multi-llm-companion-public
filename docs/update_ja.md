# v1.1.1への更新手順

v1.0.0・v1.0.1・v1.1.0から、会話・記憶・個人設定を引き継ぐ手順です。**旧版を上書きせず、新しいフォルダーへ展開します。** 旧版とバックアップは、更新後の動作を確認するまで残してください。同じ会話DBを新旧のアプリから同時に開かないでください。

v1.1.1では、記憶候補の件数制限、返答・記憶の一括保存、音声認識の停止・交換、音声終了時の後始末、返信途中のキャンセルを修正しました。v1.1.0で追加した環境設定や通知機能も引き続き利用できます。Windows 11・Python 3.12 x64が必要です。依存パッケージの固定版と会話DBの保存形式はv1.0.1から変更していません。

## 1. 旧版を終了してバックアップする

1. 生成・録音・読み上げを終えるか、表示中の停止・取消ボタンで止めます。右上の **×** でアプリを終了します。
2. [バックアップと復旧](backup_and_recovery_ja.md#バックアップする) の終了確認を行います。画面が閉じても処理が残っている間はDBをコピーしません。
3. アプリの外の個人用フォルダーに、日付を付けたバックアップ先を作ります。旧版の `local` と `data` を **コピー** します。DBの横に `-wal`・`-shm` がある場合も一緒にコピーします。
4. `.env` を自分で使用している場合だけ、個人用バックアップへコピーします。隠れている場合はエクスプローラーの **表示 → 表示 → 隠しファイル** をオンにします。`.env` には認証情報が入る場合があるので、GitHubや問い合わせに添付しないでください。

通常とは別の場所へDBや素材を保存している場合は、そのファイルも保存します。バックアップを公開フォルダーへ置かないでください。画面入力方式の認証情報を保管する `%LOCALAPPDATA%\multi-llm-companion\connections` はコピー対象にしません。

## 2. 新版を別フォルダーに用意する

1. [v1.1.1の配布ページ](https://github.com/pocketrocket350/multi-llm-companion-public/releases/tag/v1.1.1) の **Assets** から `multi-llm-companion-v1.1.1-source.zip` と `SHA256SUMS.txt` をダウンロードします。
2. [ハッシュの確認手順](release_ja.md#zipの破損取り違えを確認する) で値が一致することを確認します。一致しなければ実行しません。
3. ZIPを右クリック → **すべて展開** で新しいフォルダーへ展開します。旧版のフォルダーを展開先に指定しないでください。
4. 新版の `setup_windows.bat` をダブルクリックし、**セットアップが正常に終わりました** を待ちます。ネット接続が必要です。旧版の `.venv` や「起動」ショートカットはコピーしません。
5. 新版フォルダー内の **起動** を開き、Mockで会話画面が出ることを確認して終了します。初回はAPIキー不要です。ただし、過去に保存先を指定する `MULTI_LLM_COMPANION_HOME` を設定した場合は、先に次の説明を読み、下の2行で起動してください。

過去に `MULTI_LLM_COMPANION_HOME` を設定した場合、その値が旧版を指す可能性があります。新版のフォルダーのアドレス欄に `cmd` と入力し、次を順に実行すると、このコマンド画面からの起動だけ保存先の指定を外せます。Windowsに保存した環境変数は書き換えません。この変数が旧版を指している間は、本書の以後の「起動」・再起動もこの方法で行ってください。旧版へ戻すときは、旧版のフォルダーで同じ2行を実行します。

```bat
set "MULTI_LLM_COMPANION_HOME="
run.bat
```

## 3. 個人データを新版へコピーする

1. 新旧のアプリが終了していることを確認します。
2. 新版内の `local` と `data` を、それぞれ `local-before-update`、`data-before-update` に名前変更します。同じ名前がある場合は別の名前を付けて退避します。
3. 手順1で保存したバックアップの `local` と `data` を、新版フォルダーへ **コピー** します。移動は使いません。
4. 旧版で `.env` を使っていた場合だけ、新版の見本 `.env` を別名へ退避してからバックアップの `.env` をコピーします。Windows環境変数方式は、同じWindows利用者なら従来の値をそのまま利用できます。
5. 保存先を自分で変更していた場合は、起動前に `local/app.yaml` の `database_path` と設定ファイルの参照先、素材の絶対パスを確認します。既定の `database_path: data/conversations.db` なら、新版の `data` 内のコピーを使います。旧版のDBへの絶対パスが残っている場合は、新版へコピーしたDBの場所へ変更するまで起動しないでください。
6. 新版フォルダー内の **起動** を開きます。接続情報が不足していれば環境設定が開くので、次の手順で設定します。

画面サイズ、通知の設定などは同じWindows利用者のアプリコピーで共有されます。同じPCで更新するときは通常、レジストリの書き出し・読み込みは不要です。別PCへの移行時だけ [画面の好みの保存](backup_and_recovery_ja.md#画面の好みも保存する場合) を参照してください。

## 4. 接続情報を確認する

従来の環境変数方式を続ける場合は、**設定 → 環境設定 → LLM・VoiSona Talkの接続設定** を開き、**環境変数で設定** がオンであることと、使用するLLM接続先を確認します。値を変更しなければ保存は不要です。

画面から入力する場合は、次の順で操作します。別フォルダーへ移ると保存済みの暗号化接続情報を自動で引き継がないため、以前この方式を使っていた場合も再入力します。

1. **設定 → 環境設定 → LLM・VoiSona Talkの接続設定** を開きます。
2. **環境変数で設定** のチェックを外します。
3. 接続先を選び、URL・モデル名・APIキーを入力します。必要なら **接続先を追加** でOpenAI互換の接続先を登録します。
4. 読み上げを使う場合はVoiSona Talkを起動し、読み上げをオンにして、URL・REST API用のユーザー名・パスワードを入力します。**ボイス一覧から選ぶ → 名前を選択 → 選択** でボイス名を設定します。
5. **保存（再起動後に反映）→ アプリを終了 → 新版の起動** と操作します。入力欄が伏せ字でも、認証情報を画面写真や問い合わせへ転記しないでください。

任意の事前確認として **接続テスト**、**VoiSona Talkの接続テスト・試聴** を使えます。LLMには短い固定文を送るため料金が発生する場合があります。テストだけでは設定は保存されません。詳しくは [環境設定](environment_settings_ja.md) を参照してください。

## 5. 更新できたことを確認する

1. **履歴** を開き、以前の会話があることを確認します。**設定 → 会話 → 記憶を管理** で保存した記憶も確認できます。
2. **設定 → 診断情報** で意図したプロバイダーとモデルになっていることを確認します。
3. **設定 → 表示 → フローティング通知** で、**記憶の通知を表示** と **通常の案内を表示**、それぞれの表示時間を変更できます。変更は自動保存され、時間は次の通知から反映されます。初期値は両方オン、記憶6秒、通常3.5秒です。
4. 意図した接続先で短い会話を行い、終了して再起動します。新しい会話が履歴に残り、通知設定も保持されれば移行の確認は完了です。音声を使う場合は、選んだボイスで聞こえることも確認します。

## 問題があった場合に戻す

履歴・記憶の欠落、違う保存先の使用、接続エラーが続く場合は、新版での送信を止めて終了します。元のフォルダー内の **起動** から旧版へ戻れます。元のDB、個人設定、バックアップは削除しません。

新版で追加した会話は新版のコピーに保存され、旧版へは自動で合流しません。旧版のDBへ新版のDBを上書きしないでください。新版のコピーを残したまま、発生した操作と日本語のエラー表示を報告してください。認証情報・会話本文・DBファイル・個人設定を添付する必要はありません。

接続画面の未保存の変更は **キャンセル** で取り消せます。通知は **設定 → 表示** で両方をオン、記憶6秒、通常3.5秒にすれば初期値へ戻ります。同じWindows利用者で共有する画面設定を変更していた場合、旧版へ戻ってもその一部は引き継がれます。
