## 1. 製品の目的

利用者がWindows PC上で、AIアバターと文字または音声を使って自然に会話できる常駐型コンパニオンを提供します。

基準環境は次の組み合わせです。

- 利用者が選択するOpenAI互換LLM API、または外部APIを使わないMock Provider
- VoiSona Talkによる日本語音声合成
- WhisperまたはVoskによる日本語音声認識
- 利用者が正規に入手した雨衣の公式PMXモデル
- 利用条件を確認してローカル登録したVMDモーション

公開リポジトリは特定キャラクターに依存しない会話エンジンとして維持します。雨衣のPMX、テクスチャ、VoiSonaボイスライブラリ、公式画像、公式人格設定、再配布条件を満たさないVMDは公開物へ含めません。

## 2. Grok Companionを使う評価基準

Grok Companionは、実装方式や全機能を複製する対象ではなく、次の利用体験を評価するためのベンチマークです。

1. 利用者が話し終えてから長く待たされず、音声会話が自然に往復する。
2. 利用者が話し始めたら、古い音声と動作を速やかに止められる。
3. アバターの口、表情、視線、姿勢、身振りが発話内容と会話状態に合う。
4. 同じ表情や動作を機械的に繰り返さず、存在感がある。
5. 会話をまたいで利用者の明示情報と話題を安全に継続できる。
6. 長時間利用しても遅延、メモリ、音声キュー、描画負荷が増え続けない。

2026年8月30日時点のGrok公式情報では、低遅延の音声会話、会話をまたぐ記憶、リアルタイム検索、ファイル・画像理解、カメラ映像を使う音声会話が案内されています。

- https://x.ai/grok
- https://x.ai/news/grok-4
- https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech

本製品のv1.0では、Grokの画像・動画生成、すべての検索・ツール機能、モバイル対応を再現しません。低遅延音声、表情、視線、モーション、人格、記憶、安定運用というコンパニオンの中核体験を優先します。2026-09-22の再編では、現在情報などの機能拡張と画面再設計を先に行う順番を定めました。2026-10-05以降は採用済み機能と画面を保持し、長時間安定性・会話の待ち時間・記憶の連続性を仕上げます。雨衣をタスク管理ツールにすることを目的としません。

## 3. 状態の定義

ロードマップでは、実装状態を次の4種類に分けます。

| 状態 | 意味 |
| --- | --- |
| 受入完了 | 自動テストだけでなく、必要な実画面・実音声確認にも合格している |
| 基盤完了 | 実装と回帰テストはあるが、見た目、音、実コンテンツ、長時間品質の受入が未完了 |
| 計画済み | 要件と完了条件を定義し、これから実装または検証する |
| 判断待ち | 必要性、権利、外部送信、安全性を評価して個別の採否を決める。調査の先行と機能の採用承認は区別する |

コード経路、設定項目、管理画面、人工テストデータが存在するだけでは「受入完了」としません。利用者から見えない表情、登録されていないモーション、測定されていないリアルタイム性は未完成として扱います。

1. 文字と音声の両方で会話でき、基準条件で音声応答開始の中央値が1.5秒以内、95%点が2.5秒以内である。
2. 利用者が話し始めるか停止操作を行ってから300 ms以内を目標に再生を止め、古い音声・表情・視線・動作を再開しない。
3. 口形が音声機器の実再生位置に同期し、先頭欠落、末尾欠落、発話後の口形再開がない。

## 6. 最終アーキテクチャ

### 6.1 責務の分離

- UI: PySide6でチャット、設定、記憶管理、マイク操作、状態表示、アバター表示を提供する。再設計では、日常の会話面と、必要時だけ開く設定・詳細診断を分ける。
- 会話サービス: 人格、会話方針、履歴、要約、記憶、Provider呼出しを統合する。
- Provider: MockとOpenAI互換APIを共通インターフェースで切り替える。
- 音声入力: 録音、音声区間検出、途中認識、確定認識を会話送信から分離する。
- 音声出力: 合成依頼、データ受信、再生開始、実再生位置、再生終了を別状態として扱う。
- 表現計画: 一つの会話意図から、音声、表情、視線、ジェスチャー、自然動作へ別々の上限付き強度を渡す。
- MMDランタイム: VMD、ボーン、IK、物理、スキニング、材質、描画を順序どおりに評価する。
- 永続化: SQLiteの会話履歴と、利用者が管理できる長期記憶を分離する。
- ローカル素材: PMX、テクスチャ、VMD、権利確認記録を`local`配下で管理し、外部へ自動送信しない。

### 6.2 会話ターン

```text
文字・音声入力
    → 新しいターン世代を発行
    → 人格・文脈・記憶を構成
    → Providerへ送信
    → 応答文・感情・動作意図・視線意図を受信
    → 音声と表現を準備
    → 実音声再生時計に口形と会話表現を同期
    → 再生終了後に待機状態へ戻る
```

新しい入力、停止、録音開始は同じターン世代を無効化します。無効になった認識、LLM応答、音声、表情、視線、動作、非同期姿勢は再適用しません。

### 6.3 MMD表示

```text
PMX・VMD読込
    → VMD補間
    → PMX変形順・付与変形・IK
    → Bullet 2.75物理
    → 物理後ボーン
    → BDEF・SDEFスキニング
    → 口・表情・材質・UVモーフ
    → OpenGL描画
```

変更されていないPMX、テクスチャ、材質、VMDは通常更新ごとに再読込・再変換・再転送しません。軽い口形、瞬き、視線と、重い物理・全頂点計算を分離します。

## 10. フェーズを停止する条件

次のいずれかが発生した場合、そのフェーズを完了にせず原因診断へ戻ります。

- 文字チャット、履歴、音声停止が使えなくなる。
- 音声の先頭・末尾欠落、口形同期ずれ、古いターンの再適用が発生する。
- 姿勢飛び、足浮き、大きな衣装貫通、物理発散、非数値が発生する。
- 周期処理が継続的に設定周期を超える。
- 実画面で判別できない表情や、登録されていない動作を完成扱いにする。
- 権利未確認素材、秘密情報、利用者データが公開対象へ混入する。
- 自動テストの削除、無効化、基準緩和でしか合格できない。
- 同じ仮説の修正が一度失敗した後、原因を確定せず同じ調整を繰り返す。
