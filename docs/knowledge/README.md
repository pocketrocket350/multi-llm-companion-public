# 開発知識の再利用

このフォルダーは、調査や修正で得た知見を次回以降のCodex作業で再利用するための索引です。アプリが利用者との会話から保存する長期記憶とは別物であり、`MemoryService`、`data/conversations.db`、会話プロンプトには接続しません。

## 情報の置き場所

| 場所 | 用途 | Git |
| --- | --- | --- |
| `local/diagnostics/` | 生の計測、診断ログ、評価結果 | 対象外 |
| `local/dev-knowledge/candidates/` | 単発の観測、未確認の仮説、失敗記録、証拠への参照 | 対象外 |
| `docs/knowledge/` | 検証済みで、秘密情報と権利対象を除いた再利用可能な知見 | 対象 |
| `docs/adr/` | 複数案を比較した、変更コストの大きい設計判断 | 対象 |
| `AGENTS.md` | 毎回必要な横断的不変条件と、この索引を読む条件 | 対象 |

候補を記録する必要が生じたときだけ `local/dev-knowledge/candidates/` を作成します。候補は正式な根拠や作業指示ではありません。

## 作業開始時の検索

1. 今回の対象、症状、外部API、関連コンポーネントを短い語に分けます。
2. 下の索引と `rg` で、同じ対象や症状の記録を探します。
3. 関係する記録だけを原則3件以内で読みます。全記録を毎回プロンプトへ入れません。
4. `scope`、`last_verified`、証拠、反証、失効条件を確認します。
5. 対象バージョンが変わった、証拠を再現できない、反証が未解決の記録は、確定事項として使いません。

5ファイル以上を横断する検索や大量照合は、`AGENTS.md`の規則に従って`luna_worker`へ委任できます。重要な判断と採否は親エージェントが行います。

## 記録と昇格

通常の作業ログや既存資料の言い換えは記録しません。将来の調査、設計、修正方針を変える知見だけを候補にします。

状態は次の意味で使います。

- `candidate`: 単発の観測または未確認の仮説。`local/dev-knowledge/candidates/`だけに置く。
- `validated`: 原因と適用条件を証拠で確認し、追跡可能な知識として利用できる。
- `promoted`: `AGENTS.md`またはADRへ、より強い規則や設計判断として反映済み。
- `retired`: 反証、仕様変更、実装変更により通常は使用しない。削除せず理由を残す。

候補を作るときは[_template.md](_template.md)を`local/dev-knowledge/candidates/`へ複製し、`status: candidate`に変更します。この段階では索引へ追加しません。下の条件を満たした後、秘密情報と権利対象を除いた記録を`docs/knowledge/`へ移し、`status`を`validated`または`promoted`にしてから索引へ追加します。

`docs/knowledge/`へ昇格するには、原則として次をすべて満たします。

1. 独立した2件以上の実行または障害で、同じ機序を確認した。
2. 同じ条件の修正前後で、結果を比較できる証拠がある。
3. 未解決の反証がなく、適用範囲と失効条件を説明できる。
4. APIキー、認証情報、利用者の会話、外部LLMの生回答、第三者素材を含まない。
5. 親エージェントが証拠を確認した。高リスクな判断はSol Advisorの読み取り専用レビューも通す。

一度の重大障害から昇格する場合は、原因を直接示す計測、回帰テスト、必要な実機確認が揃い、同じ誤りを防ぐ効果が明確な場合に限ります。回数だけで一般化しません。

設計判断は[ADRの規則](../adr/README.md)へ、複数領域で毎回必要な行動規則だけを`AGENTS.md`へ昇格します。昇格時は既存規則と統合し、`AGENTS.md`を事例集にしません。自動昇格は行いません。

## 安全性

- 外部サイト、投稿、外部リポジトリは着想または参考資料であり、プロジェクト内の証拠ではありません。
- `local/`や`data/`の内容を追跡対象へコピーする前に、秘密情報、個人情報、利用者会話、権利対象がないことを確認します。
- 生ログや生成文をそのまま保存せず、再現に必要な事実と追跡可能な証拠パスだけを残します。
- 記録の内容が現行コードや一次資料と矛盾する場合は、記録より現行の証拠を優先します。

## 第1段階の評価

次の5～10件の関連作業で、以下を記録して運用の有効性を判断します。

- 既存知識が調査方針や修正方針を変えた件数
- 同じ失敗または同じ仮説を繰り返した件数
- 原因確定までの試行回数と所要時間
- 古い、誤った、適用範囲外だった知識の件数
- `AGENTS.md`の行数と文字数
- 追跡対象への秘密情報混入件数。成功条件は常に0件

入力キャッシュ率やCodexの利用枠減少は、この運用だけの因果として扱いません。
